# 실습 5. 업데이트와 롤백

**무엇을 하나요**: hello를 `v1` → `v2`로 바꿉니다. 쿠버네티스가 파드를 **하나씩** 새 버전으로 바꾸는 것(롤링 업데이트)을 보고, 이전 버전으로 되돌립니다(롤백). 없는 이미지로 바꾸는 실수를 해도 기존 파드가 계속 살아 있는 것도 확인합니다. (교안 04장)

**필요한 것**: 실습 4의 Deployment `hello`(파드 3개, `hello:v1`), 실습 3에서 `kind load`로 넣은 `hello:v2`.

> **바로 가기** · [1. 지금 버전 확인](#1단계-지금-버전-확인) · [2. v2로 바꾸기](#2단계-v2로-바꾸기) · [3. 무엇이 바뀌었나](#3단계-무엇이-바뀌었나) · [4. 되돌리기 — rollout undo](#4단계-되돌리기--rollout-undo) · [5. 없는 이미지로 바꾸는 실수](#5단계-없는-이미지로-바꾸는-실수) · [끝났는지 확인](#끝났는지-확인) · [정리](#정리) · [확인 문제](#확인-문제)

## 1단계. 지금 버전 확인

```bash
cd ~/ktcloud-cloud-native-lab/lab/k8s/hello
kubectl exec deploy/hello -- wget -qO- localhost:3000
```

**이 명령은**: `kubectl exec deploy/hello` = Deployment `hello`의 파드 하나를 골라 그 안에서 실행(파드 이름을 몰라도 됨).

**이렇게 나오면 성공**: `hello, docker`

## 2단계. v2로 바꾸기

`deploy.yaml`의 `image: hello:v1`을 `image: hello:v2`로 고칩니다.

```bash
nano deploy.yaml          # image: hello:v1 → image: hello:v2 로 고쳐 저장
kubectl apply -f deploy.yaml
kubectl rollout status deployment/hello
```

**이 명령은**: `kubectl rollout status` = 업데이트(롤아웃)가 끝날 때까지 진행 상황을 보여 줌. 끝나면 저절로 프롬프트로 돌아옵니다.

**이렇게 나오면 성공** — 마지막 줄 `successfully rolled out`

```
Waiting for deployment "hello" rollout to finish: 1 out of 3 new replicas have been updated...
Waiting for deployment "hello" rollout to finish: 2 out of 3 new replicas have been updated...
Waiting for deployment "hello" rollout to finish: 1 old replicas are pending termination...
deployment "hello" successfully rolled out
```

`1 out of 3 … 2 out of 3 …` = 새 파드를 하나 만들고, 준비되면 옛 파드를 하나 내리고를 반복합니다(롤링 업데이트). 그래서 업데이트 중에도 앱이 멈추지 않습니다.

## 3단계. 무엇이 바뀌었나

```bash
kubectl get replicaset
kubectl get pods
kubectl exec deploy/hello -- wget -qO- localhost:3000
```

**이렇게 나오면 성공**

```
NAME               DESIRED   CURRENT   READY   AGE
hello-5ffdb5bb64   3         3         3       2s
hello-d6646dd5c    0         0         0       58s
```
```
hello, 본인이름
```

- ReplicaSet이 **두 개**: 새 것(`v2`, 3개)과 옛 것(`v1`, 0개). 옛 ReplicaSet은 지우지 않고 0으로 줄여 둡니다 → 되돌릴 때 씀
- `kubectl get pods`에 옛 파드가 `Terminating`으로 잠시 남아 있습니다. 30초쯤 뒤 사라집니다

## 4단계. 되돌리기 — rollout undo

```bash
kubectl rollout history deployment/hello
kubectl rollout undo deployment/hello
kubectl rollout status deployment/hello
kubectl exec deploy/hello -- wget -qO- localhost:3000
```

**이 명령은**
- `rollout history` = 지금까지의 버전(REVISION) 목록
- `rollout undo` = 바로 전 버전으로 되돌림

**이렇게 나오면 성공**

```
REVISION  CHANGE-CAUSE
1         <none>
2         <none>
```
```
Warning: resource deployments/hello was previously managed with 'kubectl apply'. Rolling back will not update the kubectl.kubernetes.io/last-applied-configuration annotation, …
deployment.apps/hello rolled back
…
deployment "hello" successfully rolled out
hello, docker
```

- `Warning` 줄은 정상입니다. "파일(`deploy.yaml`)로 관리하던 것을 명령으로 되돌렸으니, 파일과 클러스터가 달라졌다"는 알림입니다
- 지금 `deploy.yaml`에는 아직 `hello:v2`가 적혀 있습니다. **파일도 v1으로 고쳐 맞춰 둡니다**

```bash
nano deploy.yaml          # image: hello:v2 → image: hello:v1
kubectl apply -f deploy.yaml
```

`deployment.apps/hello configured`가 나오고, 파드는 이미 v1이라 더 바뀌지 않습니다. 급할 때는 `rollout undo`로 되돌리고, 그다음 파일을 맞춰 두는 것이 순서입니다.

## 5단계. 없는 이미지로 바꾸는 실수

일부러 없는 태그 `hello:v9`로 바꿔 봅니다.

```bash
nano deploy.yaml          # image: hello:v1 → image: hello:v9
kubectl apply -f deploy.yaml
kubectl rollout status deployment/hello
```

`rollout status`가 끝나지 않습니다. 20초쯤 지켜본 뒤 **Ctrl+C**로 빠져나옵니다.

```
Waiting for deployment "hello" rollout to finish: 1 out of 3 new replicas have been updated...
^C
```

```bash
kubectl get pods
kubectl get replicaset
```

**이렇게 나오면 성공** — 새 파드 1개는 `ImagePullBackOff`, **기존 파드 3개는 `Running` 그대로**

```
NAME                     READY   STATUS             RESTARTS   AGE
hello-59db6868c7-b8kk4   0/1     ImagePullBackOff   0          20s
hello-d6646dd5c-7nmsx    1/1     Running            0          2m
hello-d6646dd5c-7rv72    1/1     Running            0          2m
hello-d6646dd5c-9mrs5    1/1     Running            0          2m
```
```
NAME               DESIRED   CURRENT   READY   AGE
hello-59db6868c7   1         1         0       20s
hello-5ffdb5bb64   0         0         0       3m
hello-d6646dd5c    3         3         3       4m
```

- 새 파드가 준비되지 않으면 쿠버네티스는 **옛 파드를 내리지 않습니다**. 실수한 업데이트라도 앱은 계속 돌아갑니다
- 이유는 `kubectl describe pod <ImagePullBackOff인 파드>`의 Events: `Failed to pull image "hello:v9": … not found`

파일을 고쳐 되돌립니다.

```bash
nano deploy.yaml          # image: hello:v9 → image: hello:v1
kubectl apply -f deploy.yaml
kubectl rollout status deployment/hello
kubectl get pods
```

**이렇게 나오면 성공**: `successfully rolled out`, `ImagePullBackOff` 파드가 `Terminating`을 거쳐 사라지고 `Running` 3개만 남음.

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `rollout status`가 끝나지 않음 | 새 파드가 준비되지 않음(이미지 없음 등) | Ctrl+C → `kubectl get pods`·`describe`로 이유 찾기 → 파일을 고쳐 다시 apply |
| `kubectl exec deploy/hello …`가 `container not found` 등으로 실패 | 고른 파드가 아직 시작 중이거나 고장 난 파드 | 몇 초 뒤 다시, 또는 `kubectl exec <Running인 파드 이름> -- …` |
| `hello, 본인이름`이 아니라 `hello, docker` | Docker 실습 7에서 v2를 만들 때 문구를 안 바꿈 | 동작은 같음. 그대로 진행 |

</details>

## 끝났는지 확인
- ☐ v2로 바꾼 뒤 `hello, 본인이름`, 되돌린 뒤 `hello, docker`
- ☐ `hello:v9`로 바꿨을 때 기존 파드 3개가 `Running`으로 남아 있었다
- ☐ 마지막에 `deploy.yaml`이 `image: hello:v1`, 파드 3개 `Running`

## 정리
- Deployment `hello`(v1, 3개)는 실습 6에서 씁니다. `deploy.yaml`은 `image: hello:v1`, `replicas: 3`인지 확인합니다

## 확인 문제
1. `kubectl rollout history deployment/hello`를 보면 REVISION 번호가 1부터 이어지지 않습니다. 번호가 어떻게 바뀌어 왔는지 4단계·5단계에서 한 일과 맞춰 설명하세요.
2. 5단계에서 `hello:v9`로 바꿨을 때 새 파드는 1개만 만들어지고 기존 파드 3개는 그대로였습니다. 왜 기존 파드를 하나도 내리지 않았을까요? (`kubectl describe deployment hello`의 `RollingUpdateStrategy` 줄을 보세요)
