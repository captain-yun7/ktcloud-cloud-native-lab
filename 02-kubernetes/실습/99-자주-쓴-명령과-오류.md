# 자주 쓴 명령과 오류

## 자주 쓴 명령

- 보기: `kubectl get` (`-o wide` `-o yaml` `-o jsonpath` `--show-labels` `-l` `-n` `-A` `-w`) · `describe` · `logs` (`deploy/이름` `job/이름` `-c 컨테이너`) · `exec` (`-- 명령`) · `top nodes/pods` · `explain`
- 만들기·바꾸기·지우기: `apply -f` · `delete` (`pod 이름` `-l` `-f` `deployment` `job` `hpa`) · `run` · `create secret generic --from-literal` · `create job/deployment … --dry-run=client -o yaml > 파일`(YAML 뼈대) · `kind load docker-image … --name lab`
- Deployment: `rollout status / history / undo / restart` · `scale` · `autoscale --cpu=50% --min --max` · `get hpa`
- 연결: `port-forward svc/이름 VM포트:서비스포트` · `get endpointslices` · 클러스터 안에서 `wget -qO- 이름` · Service `type: NodePort` + `nodePort: 30080` → VM `curl localhost:8080`
- 클러스터: `make tools / up / status / ingress / reset` (lab 폴더에서)
- Helm: `show values` · `template` · `install` · `list` · `upgrade --set` · `history` · `rollback` · `get values` · `uninstall`

## 자주 만나는 오류 한눈에

먼저 `kubectl get pods`의 `STATUS`를 보고, `kubectl describe pod <이름>`의 **Events**, 그다음 `kubectl logs`를 봅니다(교안 09장).

| STATUS·문구 | 뜻 | 먼저 해 볼 것 |
|---|---|---|
| `ErrImagePull` / `ImagePullBackOff` | 이미지를 못 받음 | Events의 이미지 이름. 내가 만든 이미지면 `kind load docker-image … --name lab`, 태그 오타 |
| `CreateContainerConfigError` | 파드가 쓸 Secret·ConfigMap이 없음 | Events의 `secret "…" not found`. 이름 확인 후 만들기 |
| `CrashLoopBackOff` / `Error` | 컨테이너가 시작했다가 계속 꺼짐 | `kubectl logs <파드>`, 이미 다시 시작했으면 `kubectl logs <파드> --previous` |
| `Pending` | 놓일 노드가 없음 | Events의 `Insufficient cpu`/`memory`(requests가 큼), PVC 이름 |
| `OOMKilled` | 메모리 limits를 넘어 강제로 꺼짐 | `describe`의 `Last State`, limits를 늘림 |
| `0/1 Running` | 실행 중이지만 준비 안 됨(readiness 실패) | Events의 `Readiness probe failed` |
| `RESTARTS`가 계속 늘어남 | liveness 실패, 또는 앱이 계속 꺼짐 | Events의 `Liveness probe failed`, `logs --previous` |
| `No resources found in … namespace.` | 그 네임스페이스에 없음(이름 오타여도 오류 없이 이렇게 나옴) | `-n` 이름, `kubectl get namespaces` |
| `The connection to the server … was refused` | 클러스터가 꺼짐 | [시작하기 전에 6](./00-시작하기-전에.md#6-클러스터가-떠-있는지-확인-실습-2부터-매번) |
| `selector does not match template labels` | Deployment의 이름표 두 곳이 다름 | `selector`와 `template.metadata.labels`를 같게 |
| `wget: bad address` / `Connection refused` | Service 이름 오타 / 엔드포인트 없음(셀렉터) 또는 targetPort 틀림 | `kubectl get svc`, `kubectl get endpointslices`(`<unset>`인지, PORTS가 앱 포트인지) |
| `502 Bad Gateway` (todo) | api가 아직 준비 전 | 몇 초 뒤 다시, readinessProbe(실습 9 확인 문제 1) |
| `Init:0/1` | init 컨테이너가 도는 중(실습 3) | 몇 초 뒤 다시. 오래 걸리면 `describe`의 Events |
| `EXTERNAL-IP <pending>` | LoadBalancer Service인데 외부 IP를 줄 곳이 없음(kind) | 정상. kind에서는 NodePort·Ingress로 |
| `provided port is not in the valid range` / `already allocated` | nodePort가 30000~32767 밖 / 이미 쓰는 번호 | `nodePort: 30080`, `kubectl get svc`로 겹치는 Service 확인 |
| `cpu: <unknown>/50%` (HPA) | 사용량을 아직 못 잼, 또는 requests 없음 | 30초 뒤 다시, `resources.requests` 확인 |
| `yaml: line N: …` | 들여쓰기·탭 | [시작하기 전에 7](./00-시작하기-전에.md#7-yaml-파일-쓰기--들여쓰기와-nano) |
