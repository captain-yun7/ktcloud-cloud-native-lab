# 시작하기 전에

실습 1을 시작하기 전에 한 번 읽어 주세요. 접속·붙여넣기·PORTS 탭은 Docker 과목과 같습니다. 자세한 설명은 [Docker 실습 문서의 시작하기 전에](../../01-docker/실습/00-시작하기-전에.md#시작하기-전에)에 있습니다.

## 1. 서버에 접속하기

- 접속 명령: `ssh ktc-sNN` — `NN`은 본인 번호 두 자리(7번이면 `ssh ktc-s07`). 비밀번호는 VM 비밀번호이고, 입력해도 화면에 보이지 않는 것이 정상입니다
- `~/.ssh/config`에 아래 네 줄이 있어야 합니다. `NN`은 두 곳입니다(7번이면 `Host ktc-s07`, `Port 22007`)

```
Host ktc-sNN
  HostName 3.39.33.142
  User lab
  Port 220NN
```

- 설정 파일 없이 한 줄로: `ssh -p 220NN lab@3.39.33.142`
- 접속할 때 브라우저가 열리며 이메일을 물으면 예전 설정이 남은 것입니다. 위 네 줄로 바꿉니다. 자세한 절차와 오류 대처는 [접속 안내](../../00-접속-안내.md)에 있습니다

## 2. 명령은 어디에 치나요

**이 문서의 명령은 전부 서버 VM의 터미널에 칩니다.** VS Code 왼쪽 아래에 `SSH: ktc-sNN`이 보이고, 터미널 맨 앞이 `lab@sNN:~$`이면 서버 VM입니다. 내 노트북의 PowerShell·macOS 터미널에서는 `ssh ktc-sNN`만 칩니다.

`kubectl`, `kind`를 찾을 수 없다는 오류가 나오면 먼저 프롬프트가 `lab@sNN`인지 봅니다. 그다음 실습 1의 2단계(도구 설치)를 했는지 봅니다.

## 3. 명령 복사해서 붙여 넣기

- 회색 코드 블록 오른쪽 위의 **복사 버튼** → 서버 터미널 클릭 → Windows **Ctrl+V**(또는 Ctrl+Shift+V, 마우스 오른쪽 버튼), macOS **Cmd+V**
- 마지막 줄이 실행되지 않고 남아 있으면 **Enter**를 한 번 더 누릅니다
- `#` 뒤는 설명(주석)이라 같이 붙여 넣어도 실행되지 않습니다
- `<이름>`처럼 꺾쇠로 감싼 부분은 본인 값으로 바꾸고 꺾쇠도 지웁니다
- **화면 예** 블록(명령이 아니라 결과만 적힌 블록)은 붙여 넣는 것이 아니라 내 화면과 비교만 합니다

## 4. 출력이 문서와 조금 달라도 되는 것

| 달라도 되는 것 | 예 |
|---|---|
| 파드 이름 뒤의 무작위 글자 | `hello-d6646dd5c-qkcbf`의 `d6646dd5c`·`qkcbf` |
| IP 주소 | 파드 `10.244.0.7`, Service `10.96.116.181` |
| 시간 | `AGE`의 `6s`, `2m`, 로그의 날짜 |
| `Terminating` 줄 | 지워지는 중인 파드. 30초쯤 뒤 사라짐(아래 5) |
| `Waiting for deployment …` 줄의 개수 | 기다린 시간만큼 줄 수가 다름 |
| 본인 이름 | `hello:v2`의 인사말 `hello, 본인이름` (Docker 실습 7에서 넣은 이름) |

**같아야 하는 것**은 "이렇게 나오면 성공"에서 짚은 값입니다(예: `Running`, `3/3`, `hello, docker`, `200`).

## 5. 멈춘 것처럼 보일 때

| 명령 | 왜 멈춰 있나 | 끝내려면 |
|---|---|---|
| `kubectl delete pod …` (hello·api 파드) | 앱이 "끝내라"는 신호를 받고도 그대로 있어서, 쿠버네티스가 **30초** 기다린 뒤 강제로 끔. 고장이 아님 | 기다리면 끝남 |
| `kubectl rollout status …` | 업데이트가 끝날 때까지 기다리는 명령. 업데이트가 실패하면 끝나지 않음 | 성공하면 저절로 끝남. 실패한 업데이트(실습 5)에서는 **Ctrl+C** |
| `kubectl port-forward …` | 내 VM의 포트를 클러스터에 이어 주는 동안 계속 켜져 있어야 함 | 다 쓰면 **Ctrl+C** |
| `kubectl get pods -w` | `-w`(watch) = 바뀔 때마다 새 줄을 계속 보여 줌 | **Ctrl+C** |

- 위 명령 말고 몇 분 넘게 움직이지 않으면 Ctrl+C로 멈추고 같은 명령을 다시 실행합니다. 그래도 같으면 질문합니다

## 6. 클러스터가 떠 있는지 확인 (실습 2부터 매번)

실습 1에서 만든 연습용 클러스터 `lab`을 과목 끝까지 씁니다. 실습을 시작할 때마다 먼저 확인합니다.

```bash
kubectl get nodes
```

**이렇게 나오면 성공**: `lab-control-plane   Ready   control-plane …`

| 화면 | 원인 | 해결 |
|---|---|---|
| `The connection to the server … was refused` / `127.0.0.1:…: connect: connection refused` | 클러스터가 없거나 꺼짐(VM을 다시 켠 경우 등) | `docker ps -a`에 `lab-control-plane`이 `Exited`면 `docker start lab-control-plane` → 1분쯤 뒤 다시(파드들이 `RESTARTS 1`로 다시 뜸). 줄이 아예 없으면 `cd ~/ktcloud-cloud-native-lab/lab && make up` |
| `NotReady` | 클러스터를 막 만들어 준비 중 | 20초쯤 뒤 다시 |
| `kubectl: command not found` | 도구가 설치되지 않았거나 새 터미널에 설정이 안 읽힘 | 실습 1의 2단계, 또는 `source ~/.bashrc` |

- 클러스터가 망가져 어떻게 해야 할지 모르겠으면 `cd ~/ktcloud-cloud-native-lab/lab && make reset`(지우고 새로 만듦, 1분 안쪽). 단 클러스터 안에 만든 것(파드·데이터)도 모두 사라지므로, 실습 3부터 다시 하거나 질문합니다

## 7. YAML 파일 쓰기 — 들여쓰기와 nano

쿠버네티스에는 "무엇을 만들지"를 **YAML 파일**에 적어 넘깁니다(Docker 실습 13의 `compose.yaml`과 같은 형식).

- **들여쓰기는 스페이스 2칸**, **탭 금지**. YAML은 들여쓰기로 "무엇 아래에 무엇이 있는지"를 나타내므로 칸 수가 틀리면 오류가 납니다
- 줄 앞의 `- `(빼기 + 한 칸) = 목록의 한 항목. 예: `containers:` 아래 `- name: hello`는 "컨테이너 목록의 첫 번째"
- 파일 만들기: `nano 파일이름` → 문서의 내용을 붙여 넣기 → **Ctrl+O → Enter**(저장) → **Ctrl+X**(나가기)
- 고치기: `nano 파일이름` → 화살표로 이동해 고치기 → 저장·나가기
- 들여쓰기가 꼬여서 어디가 틀렸는지 모르겠으면 **파일을 지우고 처음부터 다시 붙여 넣는 것**이 가장 빠릅니다: `rm 파일이름` → `nano 파일이름`

| 오류 문구 | 원인 | 해결 |
|---|---|---|
| `yaml: line 6: found character that cannot start any token` | 6번째 줄에 **탭** | 그 줄의 탭을 지우고 스페이스로 |
| `yaml: line 8: mapping values are not allowed in this context` | 8번째 줄 들여쓰기가 위아래 줄과 안 맞음 | 문서의 내용과 칸 수를 맞춤(또는 지우고 다시 붙여 넣기) |
| `no kind "pod" is registered for version "v1"` | `kind: Pod`의 대소문자 틀림(`pod`) | `Pod`, `Deployment`, `Service`처럼 첫 글자 대문자 |
| `error: the path "pod.yaml" does not exist` | 지금 폴더에 그 파일이 없음 | `pwd`로 위치, `ls`로 파일 이름 확인 |

## 8. 터미널 두 개와 브라우저 (PORTS 탭)

`kubectl port-forward`는 켜 둔 채로 써야 해서 터미널이 두 개 필요합니다(실습 6·7·8, 미션). VS Code 터미널 패널 오른쪽 위의 **`+`** 로 하나 더 엽니다. 처음 연 것을 **터미널 1**, 새로 연 것을 **터미널 2**라고 부릅니다.

브라우저로 보려면 Docker 과목처럼 VS Code **PORTS** 탭에서 포트를 이어 줍니다([자세히](../../01-docker/실습/00-시작하기-전에.md#8-브라우저로-서버의-웹-페이지-보기-ports-탭)): PORTS 탭 → **Forward a Port** → 포트 번호 → Enter → 지구 아이콘(Open in Browser).

## 9. Docker 과목에서 만든 것이 없을 때

이 과목은 Docker 과목에서 만든 **저장소 폴더**와 **이미지 두 개**(`hello:v1`, `hello:v2`)를 그대로 씁니다. 먼저 있는지 봅니다.

```bash
ls ~/ktcloud-cloud-native-lab/lab/docker      # files  hello  README.md  todo
docker image ls hello                          # hello:v1, hello:v2 두 줄
```

**저장소 폴더가 없으면**(`No such file or directory`):

```bash
cd ~
git clone https://github.com/captain-yun7/ktcloud-cloud-native-lab.git
```

**저장소는 있는데 `lab/k8s` 폴더가 없으면**(이 과목 자료가 추가되기 전에 받은 경우): `cd ~/ktcloud-cloud-native-lab && git pull`

**이미지가 없으면**(`docker image ls hello`가 제목 줄만 나오면) — Docker 실습 7을 다시 하는 것과 같습니다. 아래를 그대로 붙여 넣습니다.

```bash
cd ~/ktcloud-cloud-native-lab/lab/docker/hello
git checkout app.js                     # app.js를 처음 받은 상태(hello, docker)로 되돌림
cat > Dockerfile <<'END'
FROM node:22-alpine
WORKDIR /app
COPY . ./
RUN npm install
EXPOSE 3000
CMD ["node", "app.js"]
END
docker build -t hello:v1 .
sed -i 's/hello, docker/hello, <이름>/' app.js      # <이름>을 본인 이름으로 바꿔서
docker build -t hello:v2 .
docker image ls hello
```

- `cat > Dockerfile <<'END'` … `END` = 그 사이의 여섯 줄을 `Dockerfile`로 저장(nano로 쓰는 것과 같은 결과)
- `sed -i 's/A/B/' app.js` = `app.js` 안의 A를 B로 바꿈. 예: `s/hello, docker/hello, 홍길동/`
- `docker` 명령이 `permission denied`면 Docker 실습 4(설치·docker 그룹)를 먼저 끝냅니다

## 이 문서에 나오는 말

| 말 | 쉬운 뜻 |
|---|---|
| 클러스터 | 컨테이너를 실행하는 컴퓨터(노드) 여러 대를 하나로 묶은 것. 이 과목의 클러스터 이름은 `lab` |
| 노드 | 클러스터 안의 컴퓨터 한 대. kind에서는 Docker 컨테이너 하나(`lab-control-plane`)가 노드 |
| 컨트롤 플레인 | 클러스터의 두뇌. 명령을 받고, 원하는 상태를 기억하고, 맞춤 |
| kind | 내 VM 안에 연습용 클러스터를 만드는 도구(Kubernetes IN Docker) |
| kubectl | 클러스터에 명령을 보내는 프로그램. 이 과목 내내 씀 |
| 매니페스트 | 만들 것을 적은 YAML 파일(`pod.yaml`, `deploy.yaml` …) |
| Pod (파드) | 쿠버네티스가 실행하는 가장 작은 단위. 컨테이너 하나(또는 몇 개)를 감싼 것 |
| 사이드카 · init 컨테이너 | 한 파드 안에서 앱 옆에 붙어 계속 도는 컨테이너 · 앱보다 먼저 한 번 실행하고 끝나는 컨테이너(실습 3) |
| Deployment | "이 이미지로 파드 N개를 유지해 줘"라는 요청서. 지워지면 다시 만들고, 이미지를 바꾸면 하나씩 교체 |
| ReplicaSet | Deployment가 만드는, 파드 개수를 세어 맞추는 것. 버전(이미지)마다 하나 |
| StatefulSet · DaemonSet · Job · CronJob | Deployment 말고 파드를 관리하는 종류. 파드마다 고정 이름·저장 공간 · 노드마다 하나 · 한 번 실행하고 끝 · 시간마다 Job(실습 4) |
| 라벨 · 셀렉터 | 라벨 = 파드에 붙인 이름표(`app=hello`), 셀렉터 = "이 이름표를 단 파드"를 고르는 조건 |
| Service | 바뀌는 파드들 앞에 둔 바뀌지 않는 이름·주소. 이름(`hello`)으로 부르면 살아 있는 파드로 넘겨 줌 |
| 엔드포인트 | Service가 지금 요청을 넘겨 줄 파드들의 주소 목록 |
| Service 종류 (`type`) | ClusterIP(기본값, 클러스터 안에서만) · NodePort(노드의 30000번대 포트로 밖에서) · LoadBalancer(클라우드가 주는 외부 IP로)(실습 6) |
| port-forward | 내 VM의 포트를 클러스터 안의 Service·파드에 잠시 이어 주는 것 |
| 네임스페이스 | 클러스터 안의 폴더. 이름이 같아도 네임스페이스가 다르면 다른 것. `-n 이름`으로 고름 |
| ConfigMap · Secret | 이미지 밖에서 넣는 설정 · 비밀번호 같은 비밀 값 |
| PVC · PV | 저장 공간 요청서 · 실제로 만들어진 저장 공간. 파드를 지워도 남음 |
| 테이블 (DB) | DB 안에서 데이터를 줄 단위로 담아 두는 곳. todo의 할 일은 postgres의 `todos` 테이블에 들어감. 문서의 표와는 다른 뜻 |
| emptyDir | 파드 안의 임시 빈 폴더. 컨테이너끼리 같이 쓰고, 파드를 지우면 함께 사라짐(실습 3) |
| Probe | 쿠버네티스가 파드를 주기적으로 검사하는 것. readiness(요청 받을 준비가 됐나), liveness(살아 있나) |
| requests · limits | 파드가 쓸 CPU·메모리의 예약량 · 최대량 |
| HPA | CPU 사용량을 보고 Deployment의 파드 개수를 자동으로 바꾸는 것(실습 10) |
| Ingress | 주소 하나(VM 80번)로 들어온 요청을 이름에 따라 여러 Service로 나눠 보내는 규칙 |
| Helm · 차트 | 매니페스트 묶음을 한 번에 설치·업그레이드·되돌리는 도구 · 그 묶음 |

## Docker에서 하던 일, 쿠버네티스에서는

| Docker에서 | 쿠버네티스에서 | 실습 |
|---|---|---|
| `docker run -d --name hello hello:v1` | Pod / Deployment YAML + `kubectl apply -f` | 3·4 |
| `docker ps` | `kubectl get pods` | 3~ |
| `docker logs hello` | `kubectl logs <파드>` | 3~ |
| `docker exec hello …` | `kubectl exec <파드> -- …` | 3~ |
| `docker rm -f hello` | `kubectl delete pod <파드>` (Deployment가 있으면 다시 생김) | 3·4 |
| `-p 8000:3000` | Service(`port: 80` → `targetPort: 3000`) + `kubectl port-forward`, 또는 `type: NodePort` | 6 |
| 같은 네트워크 안에서 이름(`db`)으로 부르기 | Service 이름(`db`, `api`)으로 부르기 | 6·7 |
| `-e DB_HOST=db` / compose의 `environment:` | ConfigMap · Secret | 7 |
| 볼륨 `-v db-data:/var/lib/postgresql/data` | PVC | 8 |
| `docker compose up -d` | `kubectl apply -f` (파일 여러 개) | 7 |
| 컨테이너가 죽으면 내가 다시 `up` | 쿠버네티스가 다시 띄움 | 4·9 |
