# 실습 1. 도구 설치와 첫 클러스터

**무엇을 하나요**: 쿠버네티스 도구(`kubectl`·`kind`·`helm`)를 설치하고, 내 VM 안에 연습용 클러스터 `lab`을 만듭니다. 클러스터의 노드가 사실은 Docker 컨테이너라는 것도 `docker ps`로 확인합니다. (교안 02장)

**필요한 것**: Docker 과목에서 받은 저장소 `~/ktcloud-cloud-native-lab`, Docker가 설치된 VM(Docker 실습 4). 없으면 [시작하기 전에 9](./00-시작하기-전에.md#9-docker-과목에서-만든-것이-없을-때).

## 1단계. 저장소를 최신으로

```bash
cd ~/ktcloud-cloud-native-lab && git pull
ls lab
```

**이 명령은**: `git pull` = 저장소에 새로 올라온 파일을 받음. 이 과목용 `lab/k8s` 폴더가 이때 들어옵니다.

**이렇게 나오면 성공**: `ls lab`에 `docker`, `k8s`, `kind`, `Makefile`이 보입니다.

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `cd: … No such file or directory` | 저장소를 받지 않음 | [시작하기 전에 9](./00-시작하기-전에.md#9-docker-과목에서-만든-것이-없을-때)의 `git clone` |
| `ls lab`에 `k8s`가 없음 | `git pull`이 실패함 | `git pull`의 마지막 줄을 보고 질문 |

</details>

## 2단계. 도구 설치

```bash
cd ~/ktcloud-cloud-native-lab/lab
make tools
source ~/.bashrc
kubectl version --client
kind version
```

**이 명령은**
- `make tools` = 이 과정에서 쓰는 도구를 정해진 버전으로 설치(`lab/.mise.toml`에 적힌 버전). 처음에는 도구 11개를 내려받느라 시간이 걸립니다(실측 20초 안쪽, 여럿이 동시에 받으면 더 걸릴 수 있음). 중간에 `mise WARN … overrides the global config` 줄이 여러 개 나와도 정상입니다. 마지막에 `설치된 버전:` 목록이 나오면 끝
- `source ~/.bashrc` = 방금 설치한 도구를 **지금 터미널에서** 바로 쓰도록 설정을 다시 읽음(새 터미널은 자동)

**이렇게 나오면 성공**

```
Client Version: v1.37.0
Kustomize Version: v5.8.1
kind v0.33.0 go1.26.7 linux/amd64
```

| 도구 | 하는 일 |
|---|---|
| `kubectl` | 클러스터에 명령을 보냄. 이 과목 내내 씀 |
| `kind` | Docker 컨테이너를 노드로 삼아 연습용 클러스터를 만듦 |
| `helm` | 매니페스트 묶음을 설치하는 도구(실습 12) |

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `kubectl: command not found` | `source ~/.bashrc`를 빠뜨림 | `source ~/.bashrc` 또는 터미널을 새로 열기 |
| `make: *** No rule to make target 'tools'.  Stop.` | `lab` 폴더가 아닌 곳에서 실행 | `cd ~/ktcloud-cloud-native-lab/lab` 후 다시 |

</details>

## 3단계. 클러스터 만들기

**반드시 `lab` 폴더에서** 실행합니다.

```bash
make up
```

**이 명령은**: `make up` = `kind create cluster`로 클러스터 `lab`을 만들고, 자원 사용량을 보는 도구(metrics-server)를 설치함. 처음에도 30초 안쪽입니다(실측 22초, 노드 이미지를 받는 시간 포함).

**이렇게 나오면 성공** — 화면 예. 마지막에 `준비 완료. 확인: make status`

```

 ✓ Ensuring node image (kindest/node:v1.37.0) 🖼
 ✓ Preparing nodes 📦
 ✓ Writing configuration 📜
 ✓ Starting control-plane 🕹️
 ✓ Installing CNI 🔌
 ✓ Installing StorageClass 💾
Set kubectl context to "kind-lab"
…
준비 완료. 확인: make status
```

| 화면 | 원인 | 해결 |
|---|---|---|

## 4단계. 노드가 준비됐는지 보기

```bash
kubectl get nodes
```

**이 명령은**: `kubectl get nodes` = 클러스터의 노드(컴퓨터) 목록. `kubectl get <종류>`가 이 과목에서 가장 많이 치는 명령입니다.

**이렇게 나오면 성공** — `STATUS`가 `Ready`

```
NAME                STATUS   ROLES           AGE   VERSION
lab-control-plane   Ready    control-plane   26s   v1.37.0
```

- 만든 직후에는 `NotReady`일 수 있습니다(네트워크 구성 요소가 뜨는 중). 20초쯤 뒤 다시 칩니다
- 노드가 하나뿐입니다. 이 노드가 컨트롤 플레인(두뇌)과 일하는 노드를 겸합니다(교안 01장의 구조 그림)

## 5단계. 노드는 Docker 컨테이너

```bash
docker ps --format "{{.Names}}  {{.Image}}"
kind get clusters
kubectl config current-context
```

**이렇게 나오면 성공**

```
lab-control-plane  kindest/node:v1.37.0
lab
kind-lab
```

- kind = **K**ubernetes **in** **D**ocker. 노드가 VM이 아니라 Docker 컨테이너 `lab-control-plane`입니다. 진짜 회사에서는 서버(VM) 여러 대가 노드이고, 우리는 VM 한 대 안에 연습용으로 만듭니다
- `kind get clusters` = 내 VM의 kind 클러스터 이름, `kubectl config current-context` = kubectl이 지금 명령을 보내는 곳

## 끝났는지 확인
- ☐ `kubectl version --client`에 `v1.37.0`
- ☐ `kubectl get nodes`에 `lab-control-plane   Ready`
- ☐ `docker ps`에 `lab-control-plane`

## 정리
- 클러스터 `lab`은 **과목 끝까지 계속 씁니다**. 지우지 마세요(`make down`은 클러스터 삭제)
