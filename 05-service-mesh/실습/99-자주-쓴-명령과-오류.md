# 자주 쓴 명령과 오류

## 자주 쓴 명령

| 명령 | 뜻 |
|---|---|
| `kubectl annotate ns <ns> linkerd.io/inject=enabled` | Linkerd 주입 표시 (끝에 `-` 붙이면 지움) |
| `kubectl label ns <ns> istio-injection=enabled` | Istio 주입 표시 |
| `kubectl -n <ns> rollout restart deploy` | 파드를 다시 만들어 주입 적용·해제 |
| `linkerd viz stat · edges · tap` | 성공률·RPS·지연 / 누가 누구를 부르나·mTLS / 요청 하나하나 |
| `linkerd viz edges deploy -n <ns> -o wide` | 보낸 쪽·받은 쪽 신분(서비스 계정) |
| `kubectl -n <ns> set serviceaccount deploy <이름> <계정>` | 파드가 쓸 서비스 계정 바꾸기 (= 메시 신분 바꾸기) |
| `kubectl -n <ns> get vs,dr` | Istio 규칙(VirtualService·DestinationRule) 목록 |
| `kubectl -n <ns> get peerauthentication,authorizationpolicy` | Istio mTLS·허용 정책 목록 |
| `istioctl analyze -n <ns>` | Istio 설정 점검 (잡는 것만 잡음) |
| `kubectl -n <ns> exec deploy/<이름> -c <컨테이너> -- curl -s -w " %{http_code}\n" <주소>` | 메시 안에서 요청하고 응답 코드 보기 |
| `kubectl top pods -n <ns> --containers` | 컨테이너별 CPU·메모리 |

## 자주 만나는 오류 한눈에

| 화면 | 원인 | 해결 |
|---|---|---|
| `READY 1/1` (주입했는데) | 표시만 하고 파드를 다시 안 만듦 | `rollout restart` |
| `× Gateway API CRDs are installed` | Gateway API 없음 | `make gateway-api` |
| `Please uninject the following pods …` | 주입된 파드가 남은 채 Linkerd 제거 | 표시 지우고 `rollout restart` 후 다시 |
| psql `server closed the connection unexpectedly` | Linkerd 정책이 그 신분을 허용하지 않음 | 의도한 것(실습 3). 앱이면 서비스 계정 확인 |
| 비율이 규칙과 다름 | 규칙 바꾼 직후 / 헤더 규칙이 비율 규칙 아래 | 5초 기다림 / `- match:` 묶음을 위로 |
| `no healthy upstream` (503) | subset 라벨에 맞는 파드가 없음 | DestinationRule `labels` ↔ 파드 라벨(`--show-labels`) |
| `upstream request timeout` (504) | 타임아웃 규칙에 걸림 | 의도한 것(실습 5). 아니면 `kubectl get vs`로 timeout 확인 |
| `fault filter abort` (503) | 장애 주입 규칙이 남아 있음 | `kubectl get vs`에서 `fault`가 든 규칙을 지움 |
| `RBAC: access denied` | Istio AuthorizationPolicy가 그 신분을 허용하지 않음 | `principals` 목록 확인 |
| 입구(`shop.localhost`)가 `502 Bad Gateway` | 받는 쪽이 STRICT mTLS인데 입구 Traefik은 메시 밖(평문) | 입구가 부르는 서비스만 PERMISSIVE |
| `http retry policy configured when attempts are set to 0` | `attempts: 0` + `retryOn` | `retryOn` 지움 |
