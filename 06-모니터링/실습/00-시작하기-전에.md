# 시작하기 전에

실습 1을 시작하기 전에 한 번 읽어 주세요. 접속·붙여넣기·YAML 쓰기·PORTS 탭은 앞 과목과 같습니다. 자세한 설명은 [Kubernetes 실습 문서의 시작하기 전에](../../02-kubernetes/실습/00-시작하기-전에.md)에 있습니다.

## 1. 명령은 어디에 치나요

**이 문서의 명령은 전부 서버 VM의 터미널에 칩니다.** VS Code 왼쪽 아래에 `SSH: ktc-sNN`이 보이고, 터미널 맨 앞이 `lab@sNN:~$`이면 서버 VM입니다.

- 회색 코드 블록 오른쪽 위의 **복사 버튼** → 서버 터미널에 붙여 넣기. `#` 뒤는 설명(주석)이라 같이 붙여 넣어도 실행되지 않습니다
- `<포트>`처럼 꺾쇠로 감싼 부분은 본인 값으로 바꾸고 꺾쇠도 지웁니다
- 이 과목에서 직접 쓰는 YAML·코드는 `~/mon` 폴더에 둡니다. `nano 파일`로 열어 붙여 넣습니다(저장 Ctrl+O → Enter, 나가기 Ctrl+X). 들여쓰기는 스페이스 2칸, 탭 금지

## 2. 클러스터가 떠 있는지 확인

서비스 메시 과목이 끝난 클러스터를 그대로 씁니다. 아래 세 줄로 확인합니다.

```bash
kubectl get nodes
kubectl -n shop get pods
kubectl -n istio-system get deploy
```

**이렇게 나오면 성공**: 노드 3개가 모두 `Ready`, shop의 파드 12개가 모두 `2/2 Running`(앱 컨테이너 + Istio 사이드카), istio-system에 `istiod`·`kiali`·`prometheus`.

```
NAME                READY   STATUS    ...
lab-control-plane   Ready   control-plane ...
lab-worker          Ready   <none> ...
lab-worker2         Ready   <none> ...
NAME                                     READY   STATUS    RESTARTS   AGE
adservice-649fdfd5dd-krqn2               2/2     Running   0          25h
...
NAME         READY   UP-TO-DATE   AVAILABLE   AGE
istiod       1/1     1            1           25h
kiali        1/1     1            1           25h
prometheus   1/1     1            1           25h
```

- 노드가 안 보이거나 shop 네임스페이스가 없으면 서비스 메시 [실습 1](../../05-service-mesh/실습/01-노드-3개-클러스터와-Linkerd-설치.md)(노드 3개 클러스터) · [실습 4](../../05-service-mesh/실습/04-Linkerd-지우고-Istio-todo-api-카나리.md)의 3단계(Istio) · [실습 6](../../05-service-mesh/실습/06-Online-Boutique에-Istio와-Kiali.md)(쇼핑몰)로 다시 만듭니다. 혼자 어렵다면 질문합니다
- todo(`todo` 네임스페이스)는 서비스 메시 실습 5 끝에서 지웠습니다. 실습 1의 1단계에서 다시 띄웁니다

## 3. 브라우저로 보기 — PORTS 탭과 주소

Prometheus·Grafana·Alertmanager는 브라우저로 봅니다. VS Code 아래 **PORTS** 탭에서 VM의 `80`번을 전달(Forward)하면 내 PC 쪽 포트 번호가 하나 생깁니다. 그 번호를 `<포트>`에 넣습니다.

| 화면 | 주소 | 로그인 |
|---|---|---|
| Grafana | `http://grafana.localhost:<포트>` | `admin` / `lab-grafana` |
| Prometheus | `http://prometheus.localhost:<포트>` | 없음 |
| Alertmanager | `http://alertmanager.localhost:<포트>` | 없음 |

- 로그(Loki)와 트레이스(Tempo)는 따로 화면이 없고 **Grafana 안의 Explore**에서 봅니다
- Grafana 비밀번호는 실습용으로 정해 둔 값입니다. 회사에서는 Secret에 넣고 바꿉니다

## 4. 막히면 — 질문하는 법

1. 에러의 **첫 줄**부터 읽고, 그 단계의 **이렇게 나오면?** 표와 [자주 만나는 오류 한눈에](./99-자주-쓴-명령과-오류.md#자주-만나는-오류-한눈에)에서 같은 문구를 찾아봅니다
2. 그래프가 비어 있으면 1~2분 기다립니다. Prometheus는 15~30초마다 한 번씩 값을 가져오므로, 방금 만든 것은 조금 뒤에 보입니다
3. 그래도 모르겠으면 Discord에 질문합니다. 에러는 **사진이 아니라 글자로** 붙이고, 아래 네 가지를 같이 적습니다

```
[실습 4 - 6단계] (몇 번 실습, 몇 단계)
한 일: kubectl apply -f todo-api-servicemonitor.yaml
기대: Prometheus Targets 에 serviceMonitor/todo/todo-api/0 (UP)
실제: 2분이 지나도 안 보임
해 본 것: kubectl -n todo get svc api --show-labels 결과 (그대로 붙여넣기)
```

## 이 문서에 나오는 말

| 말 | 쉬운 뜻 |
|---|---|
| 지표(메트릭) | 시간에 따라 바뀌는 숫자. 초당 요청 수, CPU 사용량, 메모리 |
| 로그 | 프로그램이 한 줄씩 남기는 기록. `"GET /api/todos HTTP/1.1" 500` |
| 트레이스 · 스팬 | 요청 하나가 지나간 길 전체 · 그 길에서 서비스 하나가 쓴 구간(시작 시각과 걸린 시간) |
| 수집 대상(target) | Prometheus가 지표를 가져가는 주소 하나. 예: `http://10.244.1.45:3000/metrics` |
| `/metrics` | 앱이 자기 숫자를 글자로 보여 주는 주소. Prometheus가 15초마다 와서 읽어 감 |
| 라벨 | 지표에 붙은 이름표. `namespace="todo"`, `code="500"` |
| counter · gauge · histogram | 늘기만 하는 숫자(요청 수) · 오르내리는 지금 값(메모리) · 구간별 개수(0.005초 안에 끝난 요청 몇 개) |
| PromQL · LogQL · TraceQL | Prometheus(지표) · Loki(로그) · Tempo(트레이스)에 물어보는 말 |
| ServiceMonitor · PodMonitor | "이 Service(파드)의 이 포트에서 지표를 가져가라"고 적는 쿠버네티스 리소스 |
| 대시보드 · 패널 | 그래프를 모아 둔 화면 · 그 안의 그래프 하나 |
| 경보(alert) | 조건이 맞으면 사람에게 알리는 것 |
| p95 | 요청 100개를 빠른 순으로 세웠을 때 95번째의 시간. "느린 쪽 손님이 겪는 시간" |
| SLI · SLO · 오류 예산 | 재는 숫자(성공 비율) · 목표(99.5%) · 그 목표가 허락하는 실패량(0.5%) |
