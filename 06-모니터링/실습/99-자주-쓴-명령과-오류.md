# 자주 쓴 명령과 오류

## 자주 쓴 명령

| 명령 | 하는 일 |
|---|---|
| `make monitoring` / `make logging` / `make tracing` | Prometheus·Grafana·Alertmanager / Loki·Alloy / Tempo 설치 (`lab` 폴더에서) |
| `kubectl -n monitoring get pods` | 모니터링 파드 상태 |
| `kubectl apply -f <파일>` | PodMonitor·ServiceMonitor·PrometheusRule·AlertmanagerConfig·Telemetry 적용 |
| `kubectl -n todo exec deploy/load -c curl -- curl -s http://api:3000/metrics` | todo-api가 내는 숫자 보기 |
| `kubectl -n monitoring logs deploy/alert-echo` | echo 서버가 받은 경보 |
| `kubectl -n todo scale deploy db --replicas=0` / `=1` | todo 장애 / 복구 |
| `kubectl -n shop scale deploy productcatalogservice --replicas=0` / `=1` | 쇼핑몰 장애 / 복구 |
| `rate(…[1m])` · `sum by (라벨) (…)` · `topk(3, …)` | 초당 증가량 · 묶어 합치기 · 큰 것만 |
| `histogram_quantile(0.95, sum by (le) (rate(…_bucket[5m])))` | p95 |
| `(… or vector(0)) / …` | 실패가 0번일 때 `No data` 대신 0 |
| `{namespace="todo"} \|= "…"` · `\| json \| 필드 > 값` · `count_over_time(…[1m])` | 로그 고르기 · JSON 필드로 거르기 · 줄 수 |
| `{resource.service.name="api.todo"}` · `{duration > 1s}` · `{rootServiceName="…"}` | 트레이스 찾기(TraceQL) |

## 자주 만나는 오류 한눈에

| 화면 | 원인 | 해결 |
|---|---|---|
| 그래프·쿼리가 비어 있음 | 막 만든 것(15~30초 간격), 범위가 짧음 | 1분 뒤 다시, `[1m]` → `[5m]` |
| 값이 두 배 | `container!=""` 또는 `reporter="destination"` 빠뜨림 | 넣기 |
| `No rule to make target …` | `lab` 폴더 밖, 저장소가 옛날 것 | `cd ~/ktcloud-cloud-native-lab && git pull && cd lab` |
| PodMonitor·ServiceMonitor를 만들었는데 대상이 안 생김 | `matchLabels`·`port` 이름이 파드·Service와 다름 | `kubectl … get pods/svc … --show-labels`와 비교, 포트는 **이름** |
| ServiceMonitor 대상이 `DOWN`, `connection reset by peer` | Istio mTLS STRICT | [실습 4 확인 문제 2](./04-todo-api에-지표-달고-가져오기.md#확인-문제) |
| Grafana 패널 `No data` | 쿼리 칸이 Builder 모드, 데이터 소스가 다름 | Code 모드, 데이터 소스 확인 |
| Loki 로그에 `failed to create fsnotify watcher: too many open files` | 내 PC(로컬)의 파일 감시 한도가 작음(서버 VM은 미리 늘려 둠) | `sudo sysctl -w fs.inotify.max_user_instances=512` ([실습 6](./06-Loki와-LogQL.md#2단계-설치--make-logging)) |
| Tempo 검색 결과가 비어 있음 | Telemetry 적용 전, 시간 범위가 과거 | 실습 7의 4단계, Last 15 minutes |
| 경보가 firing인데 받는 곳에 안 옴 | Alertmanager가 설정을 아직 안 읽음, `severity` 이름표 오타 | 1~2분 기다림, 이름표 확인 |
| `404 page not found` (브라우저) | 주소 오타 | `grafana.localhost`·`prometheus.localhost`·`alertmanager.localhost` |
