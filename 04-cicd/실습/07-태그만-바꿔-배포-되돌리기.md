# 실습 7. 태그만 바꿔 배포·되돌리기

**무엇을 하나요**: api 코드를 한 줄 고쳐 push하면 **Jenkins가 새 이미지(`jenkins-N`)를 만들어 dev 매니페스트의 태그를 바꾸고, Argo CD가 그 태그를 배포**하는 것을 끝까지 봅니다. 사람은 push만 합니다. 그다음 문제가 생겼다고 치고 Jenkins가 만든 매니페스트 커밋을 **`git revert`** 해서 이전 태그로 되돌립니다. 배포도, 되돌리기도 Git 커밋 하나입니다. (교안 06장)

**필요한 것**: 실습 5의 Jenkins(`api` 작업, 자격 증명), 실습 6의 `todo-dev` 앱(`Synced  Healthy`).

## 1단계. 지금 배포된 태그와 응답 보기

```bash
kubectl -n todo-dev get deploy api -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
kubectl -n todo-dev exec deploy/web -- wget -qO- http://api:3000/api/health; echo
```

**이 명령은**: 지금 배포된 api 이미지(태그)를 보고, web 파드 안에서 api의 상태 확인 주소(`/api/health`)를 불러 응답을 봄.

**이렇게 나오면 성공**

```
ghcr.io/<아이디>/cicd-lab/api:jenkins-2
{"ok":true}
```

## 2단계. api를 고쳐 push — Jenkins가 새 태그

`/api/health` 응답에 `version: 2`를 더합니다.

```bash
cd ~/cicd-lab && git pull
grep -n "api/health" api/app.js
sed -i "s/res.json({ ok: true })/res.json({ ok: true, version: 2 })/" api/app.js
grep -n "api/health" api/app.js
git commit -am "api: health에 version 2" && git push
```

**이 명령은**: `app.js`의 health 줄을 고쳐 push함. 이제 기다립니다. Jenkins는 2분마다 저장소를 확인하므로 **2분 안에 누르지 않은 빌드가 저절로** 시작됩니다(기다리기 싫으면 Jenkins `api` 작업에서 **지금 빌드**).

**이렇게 나오면 성공**

```
19:app.get('/api/health', (req, res) => res.json({ ok: true }));
19:app.get('/api/health', (req, res) => res.json({ ok: true, version: 2 }));
[main 1967473] api: health에 version 2
```

그 뒤 Jenkins `api` 작업에 새 빌드(예: `#4`)가 생겨 다섯 단계가 초록이 됩니다. Console Output 첫 줄은 `Started by an SCM change`, 끝 근처에 `deploy(dev): api jenkins-4 [skip ci]`.

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| push가 `rejected (fetch first)` | Jenkins 커밋을 안 받음 | 첫 줄의 `git pull`부터, 또는 `git pull --rebase` 뒤 push |
| 2분이 지나도 새 빌드 없음 | Jenkinsfile로 빌드한 적이 없어 폴링이 등록 안 됨 | 지금 빌드 한 번 |
| 두 번째 `grep`이 그대로 | sed가 못 바꿈(이미 고쳤거나 줄이 다름) | nano로 `{ ok: true, version: 2 }`로 |

</details>

## 3단계. Argo CD가 새 태그를 배포

```bash
git pull
git log --oneline -2
kubectl -n argocd get app todo-dev -w        # OutOfSync → Synced 가 보이면 Ctrl+C (몇 분 걸림)
kubectl -n todo-dev get deploy api -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
kubectl -n todo-dev exec deploy/web -- wget -qO- http://api:3000/api/health; echo
```

**이 명령은**: Jenkins가 남긴 커밋을 받아 보고, Argo CD가 그 커밋을 알아채 배포할 때까지 지켜본 뒤, 새 태그와 응답을 확인함. Argo CD는 약 3분마다 Git을 확인합니다. 기다리기 싫으면 Argo CD 화면에서 `todo-dev` → 위쪽 **REFRESH**.

**이렇게 나오면 성공**

```
5543a17 deploy(dev): api jenkins-4 [skip ci]
1967473 api: health에 version 2
NAME       SYNC STATUS   HEALTH STATUS
todo-dev   Synced        Healthy
todo-dev   OutOfSync     Healthy
todo-dev   Synced        Healthy
ghcr.io/<아이디>/cicd-lab/api:jenkins-4
{"ok":true,"version":2}
```

- push 한 번 뒤에 사람이 한 일은 없습니다. Jenkins가 이미지를 만들어 태그를 Git에 적고, Argo CD가 그 Git을 따라왔습니다

## 4단계. 되돌리기 — 매니페스트 커밋 revert

`version: 2`가 문제라고 칩니다. Jenkins가 만든 **매니페스트 커밋**(`deploy(dev): api jenkins-4`)을 되돌립니다.

```bash
git pull
git log --oneline -1
git revert --no-edit HEAD
git push
grep -A2 "name: todo-api" deploy/overlays/dev/kustomization.yaml
```

**이 명령은**: 맨 위 커밋(Jenkins의 `deploy(dev): api jenkins-4`)을 반대로 되돌리는 커밋을 만들어 올림. 이미지를 다시 만들지 않고, 태그만 `jenkins-2`로 돌아갑니다.

**이렇게 나오면 성공**

```
5543a17 deploy(dev): api jenkins-4 [skip ci]
[main 9513db2] Revert "deploy(dev): api jenkins-4 [skip ci]"
 1 file changed, 1 insertion(+), 1 deletion(-)
   5543a17..9513db2  main -> main
- name: todo-api
  newName: ghcr.io/<아이디>/cicd-lab/api
  newTag: jenkins-2
```

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `git log --oneline -1`이 `api: health에 version 2` | Jenkins 커밋을 아직 안 받음, 또는 Jenkins가 아직 안 돎 | 2~3단계가 끝났는지 확인 후 `git pull` |
| `git log --oneline -1`이 `deploy(dev): web …`(미션 2를 한 뒤) | 그 뒤 다른 매니페스트 커밋이 쌓임 | `git log --oneline -5`에서 `deploy(dev): api jenkins-N` 커밋 번호를 찾아 `git revert --no-edit <번호>` |

</details>

## 5단계. 되돌린 결과 확인

```bash
kubectl -n argocd get app todo-dev -w        # OutOfSync → Synced 가 보이면 Ctrl+C (또는 REFRESH)
kubectl -n todo-dev get deploy api -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
kubectl -n todo-dev exec deploy/web -- wget -qO- http://api:3000/api/health; echo
```

**이렇게 나오면 성공**

```
ghcr.io/<아이디>/cicd-lab/api:jenkins-2
{"ok":true}
```

| | 손으로 (K8s 과목) | Git으로 (지금) |
|---|---|---|
| 배포 | 빌드 → `kind load` → `kubectl set image` | push 한 번 → Jenkins가 태그 커밋 → Argo CD |
| 되돌리기 | `kubectl rollout undo` — 클러스터에만 남음 | `git revert` — Git 기록에 남고 클러스터가 따라옴 |
| 지금 무엇이 배포됐나 | 클러스터를 봐야 앎 | `deploy/overlays/dev/kustomization.yaml`의 `newTag` |

## 끝났는지 확인
- ☐ push만 했는데 Jenkins 새 빌드가 저절로 생겨 `deploy(dev): api jenkins-N` 커밋을 남김
- ☐ `{"ok":true,"version":2}`가 todo-dev에서 보였음
- ☐ revert 뒤 `jenkins-2`, `{"ok":true}`로 돌아옴

## 정리
- `api/app.js`에 남은 `version: 2`는 그대로 둬도 됩니다(다음에 api를 고쳐 push하면 함께 배포됨). 지우고 싶으면 `git revert --no-edit <api: health에 version 2 커밋 번호>` → push — Jenkins가 새로 빌드해 배포합니다
- Jenkins·Argo CD·`todo-dev`는 미션 2에서 계속 씁니다
