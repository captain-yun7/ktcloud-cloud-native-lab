# 시작하기 전에

실습 1을 시작하기 전에 한 번 읽어 주세요. 접속·붙여넣기·PORTS 탭은 Docker·Kubernetes 과목과 같습니다. 자세한 설명은 [Docker 실습 문서의 시작하기 전에](../../01-docker/실습/00-시작하기-전에.md)에 있습니다.

## 1. 서버에 접속하기

- 접속 명령: `ssh ktc-sNN` — `NN`은 본인 번호 두 자리(7번이면 `ssh ktc-s07`). 비밀번호는 VM 비밀번호이고, 입력해도 화면에 보이지 않는 것이 정상입니다
- `~/.ssh/config`에 아래 네 줄이 있어야 합니다. `NN`은 두 곳입니다(7번이면 `Host ktc-s07`, `Port 22007`)

```
Host ktc-sNN
  HostName 3.39.33.142
  User lab
  Port 220NN
```

- 설정 파일 없이 한 줄로: `ssh -p 220NN lab@3.39.33.142`
- 접속할 때 브라우저가 열리며 이메일을 물으면 예전 설정이 남은 것입니다. 위 네 줄로 바꿉니다. 자세한 절차와 오류 대처는 [접속 안내](../../00-접속-안내.md)에 있습니다

## 2. 명령은 어디에 치나요

**이 문서의 명령은 전부 서버 VM의 터미널에 칩니다.** VS Code 왼쪽 아래에 `SSH: ktc-sNN`이 보이고, 터미널 맨 앞이 `lab@sNN:~$`이면 서버 VM입니다. 내 노트북의 PowerShell·macOS 터미널에서는 `ssh ktc-sNN`만 칩니다.

이 과목에는 **브라우저에서 하는 단계**도 있습니다(GitHub 화면, Jenkins 화면, Argo CD 화면). 단계 제목에 "(브라우저)"라고 적었습니다. GitHub는 내 노트북 브라우저에서 바로 열고, Jenkins·Argo CD는 VS Code **PORTS** 탭으로 포트를 이어서 엽니다([PORTS 탭](../../01-docker/실습/00-시작하기-전에.md#8-브라우저로-서버의-웹-페이지-보기-ports-탭)).

## 3. 명령 복사해서 붙여 넣기

- 회색 코드 블록 오른쪽 위의 **복사 버튼** → 서버 터미널 클릭 → Windows **Ctrl+V**(또는 Ctrl+Shift+V, 마우스 오른쪽 버튼), macOS **Cmd+V**
- 마지막 줄이 실행되지 않고 남아 있으면 **Enter**를 한 번 더 누릅니다
- `#` 뒤는 설명(주석)이라 같이 붙여 넣어도 실행되지 않습니다
- `<아이디>`, `<이름>`처럼 꺾쇠로 감싼 부분은 본인 값으로 바꾸고 꺾쇠도 지웁니다
- **화면 예** 블록(명령이 아니라 결과만 적힌 블록)은 붙여 넣는 것이 아니라 내 화면과 비교만 합니다
- 워크플로 파일(`.yml`)·`Jenkinsfile`은 `nano 파일이름`으로 열어 붙여 넣고 **Ctrl+O → Enter**(저장) → **Ctrl+X**(나가기). YAML은 **들여쓰기 스페이스 2칸, 탭 금지**입니다

## 4. 출력이 문서와 조금 달라도 되는 것

| 달라도 되는 것 | 예 |
|---|---|
| 커밋 번호 | `c98718f`, `d501611..c98718f` — 사람마다, 커밋마다 다름 |
| 본인 아이디·이름 | `<아이디>`, `- 실습: <이름>` |
| 걸린 시간 | Actions 실행 31초, Jenkins 빌드 1분 — 러너·VM 상황에 따라 다름 |
| PR 번호 | `#1` — 이미 PR을 연 적이 있으면 `#2`, `#3` |
| Jenkins 빌드 번호 | `jenkins-2`, `jenkins-3` — 누른 횟수만큼 늘어남 |

**같아야 하는 것**은 "이렇게 나오면 성공"에서 짚은 값입니다(예: `main -> main`, 초록 체크, `# fail 0`, `Total: 2 (CRITICAL: 2)`, `Synced  Healthy`).

## 5. GitHub 계정과 토큰 — 비밀번호처럼

- 실습 1에서 GitHub **토큰**(`ghp_`로 시작하는 긴 글자)을 만듭니다. 토큰은 **비밀번호와 같습니다**
- 메모장·문서에 붙여 두지 않고, Discord에 붙이지 않고, 화면을 보여 줄 때는 가립니다
- 저장소 파일(`.yml`, `Jenkinsfile`)에도 **절대 적지 않습니다**. 공개 저장소라 누구나 봅니다
- 토큰이 밖에 보였으면 GitHub → Settings → Developer settings → Personal access tokens에서 **바로 지우고 새로 만듭니다**
- 토큰은 실습 1(VM 로그인)과 실습 5(Jenkins 자격 증명)에서 씁니다. 유효 기간은 30일입니다

## 6. 막히면 — 질문하는 법

1. 에러의 **첫 줄**부터 읽고, 그 단계의 **이렇게 나오면?** 표와 문서 끝의 [자주 쓴 명령과 오류](./99-자주-쓴-명령과-오류.md#자주-쓴-명령)에서 같은 문구를 찾아봅니다
2. GitHub Actions가 실패했으면 Actions 탭에서 **빨간 X가 붙은 job → 빨간 X가 붙은 단계**를 눌러 로그의 마지막 줄을 봅니다
3. 그래도 모르겠으면 Discord에 질문합니다. 에러는 **사진이 아니라 글자로** 붙이고, 아래 네 가지를 같이 적습니다

```
[실습 3 - 5단계] (몇 번 실습, 몇 단계)
한 일: git commit -am "제목 100자로 줄임" && git push && gh run watch
기대: 테스트 단계에서 실패
실제: Actions 탭에 아무것도 안 뜸
해 본 것: Actions 탭의 경고 문구 (그대로 붙여넣기)
```

- 질문할 때 비밀번호·토큰은 지우고 올립니다

## 7. 이 문서에 나오는 말

| 말 | 쉬운 뜻 |
|---|---|
| 저장소 (repository) | 프로젝트 폴더 하나와 그 변경 기록 전체. VM에 하나(`~/cicd-lab`), GitHub에 하나(`<아이디>/cicd-lab`) |
| 커밋 (commit) | 변경을 기록으로 남긴 것. 메시지와 7자리 번호(`c98718f`)가 붙음 |
| push | 내 VM의 커밋을 GitHub로 올리기. 이 과목의 모든 파이프라인은 push로 시작 |
| pull | GitHub에 있는 새 커밋을 내 VM으로 받기 |
| 브랜치 (branch) | main과 따로 고치는 갈래. 다 고치면 main에 합침 |
| PR (Pull Request) | "이 브랜치를 main에 합쳐 주세요"라는 요청. GitHub 화면에서 바뀐 줄을 보고 합침 |
| 워크플로 (workflow) | GitHub Actions가 무엇을 언제 할지 적은 파일. `.github/workflows/api.yml` |
| job | 워크플로 안의 작업 묶음. job 하나가 러너 한 대에서 돎 (`test`, `scan`, `push`) |
| step | job 안의 한 단계(명령 하나, 또는 남이 만든 Action 하나) |
| 러너 (runner) | GitHub가 실행할 때마다 빌려주는 새 가상 머신. 끝나면 사라짐 |
| 레지스트리 · GHCR | 이미지를 올려 두는 곳(Docker Hub와 같은 것) · GitHub가 주는 레지스트리 `ghcr.io` |
| 태그 | 이미지 이름 뒤 `:` 다음 부분(`:main`, `:5163e4d…`). 같은 이름의 여러 버전을 구분 |
| 시크릿 (secret) | 워크플로에 넘기는 비밀값. 이 과목은 GitHub가 실행마다 만들어 주는 `GITHUB_TOKEN`만 씀 |
| 게이트 | 기준을 못 넘으면 다음 단계로 못 가게 막는 검사(예: Trivy 취약점 검사) |
| 매니페스트 | 쿠버네티스에 무엇을 만들지 적은 YAML 파일(Kubernetes 과목과 같음) |
| kustomize · overlay | 매니페스트 묶음을 고치지 않고 환경별(dev·prod)로 값만 덮어쓰는 도구 · 그 덮어쓰는 폴더 |
| Jenkins | 내 서버에 직접 설치해 쓰는 CI 도구. GitHub Actions와 같은 일을 함 |
| 자격 증명 (credential) | Jenkins에 저장해 두는 아이디·토큰. 파이프라인 파일에 적지 않고 이름(`github`)으로 꺼내 씀 |
| GitOps | Git에 적힌 매니페스트를 기준으로 삼아 클러스터를 그대로 맞추는 방식 |
| Argo CD | 클러스터 안에서 Git을 지켜보다가 바뀌면 배포해 주는 도구 |
| 동기화 (Sync) | Argo CD가 클러스터를 Git과 같게 맞추는 것. 같으면 `Synced`, 다르면 `OutOfSync` |

## 8. 내 저장소 cicd-lab 안

Docker·Kubernetes·클라우드 보안 과목에서 쓴 todo 앱이 그대로 들어 있습니다.

| 폴더·파일 | 내용 |
|---|---|
| `api/` | todo-api (Node.js). `todo.js`(할 일 제목 정리)와 그 테스트 `test/todo.test.js`. `npm test`로 실행. Dockerfile은 클라우드 보안 실습 3의 안전한 판(`USER 1000`) |
| `web/` | todo-web (nginx). 화면과 `/api/` 요청을 api로 넘기는 설정 `default.conf` |
| `deploy/base/` | db · api · web 매니페스트 (kustomize) |
| `deploy/overlays/dev`, `prod` | 환경별 설정. 네임스페이스 `todo-dev`·`todo-prod`, 이미지 주소·태그 |
| `.github/workflows/` | 실습 3에서 만듦. GitHub Actions 워크플로 (`api.yml`, 미션 1의 `web.yml`) |
| `Jenkinsfile` | 실습 5에서 만듦. Jenkins 파이프라인 |
| `argocd/` | 실습 6에서 만듦. Argo CD 앱 설정 |
