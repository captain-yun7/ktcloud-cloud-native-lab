# 실습 3. 첫 워크플로 — 테스트·빌드·올리기

**무엇을 하나요**: push하면 GitHub가 러너(빌려주는 가상 머신)에서 **테스트 → 이미지 빌드 → GHCR에 올리기**를 자동으로 하게 만듭니다. 먼저 워크플로 **없이** 테스트가 깨지는 커밋을 올려 아무것도 막지 않는 것과, 이미지를 받을 곳이 없는 것을 봅니다. 워크플로를 넣은 뒤 같은 고장이 실패로 드러나 이미지가 올라가지 않는 것을 보고, `git revert`로 되돌립니다. Docker 과목에서 손으로 하던 `docker build`·`docker push`를 파이프라인이 합니다. (교안 03장)

**필요한 것**: 실습 2까지 한 `~/cicd-lab`, 토큰의 `workflow` 권한.

## 1단계. 워크플로 없이 깨진 커밋 올려 보기

워크플로를 만들기 **전에**, 테스트가 깨지는 변경을 그냥 올려 봅니다. api는 할 일 제목을 200자까지만 남기고(`api/todo.js`), 저장소의 테스트(`api/test/todo.test.js`)가 200을 기대합니다. 이것을 100으로 바꿉니다.

```bash
cd ~/cicd-lab
grep -n 200 api/todo.js api/test/todo.test.js
sed -i 's/MAX_TITLE = 200/MAX_TITLE = 100/' api/todo.js
git commit -am "시험: 제목 100자 (워크플로 없음)" && git push
gh run list
```

**이 명령은**: `grep -n 200` = 두 파일에서 200이 든 줄(줄 번호와 함께). `sed -i 's/A/B/' 파일` = 파일의 A를 B로 바꿈. 커밋해서 올린 뒤 `gh run list`로 이 저장소에서 돈 실행(Actions)을 봅니다.

**이렇게 나오면 성공** — push는 거부 없이 끝나고, 실행 기록은 없습니다

```
api/todo.js:2:const MAX_TITLE = 200;
api/test/todo.test.js:15:test('제목은 200자까지 남긴다', () => {
api/test/todo.test.js:16:  assert.strictEqual(cleanTitle('가'.repeat(250)).length, 200);
[main a847ff1] 시험: 제목 100자 (워크플로 없음)
 1 file changed, 1 insertion(+), 1 deletion(-)
   …  main -> main
no runs found
```

- 테스트는 저장소에 들어 있지만 **아무도 돌리지 않았습니다.** 깨진 코드가 그대로 main에 올라갔습니다. 브라우저의 **Actions** 탭도 비어 있습니다(워크플로를 시작하라는 안내만 보임)

이제 되돌립니다.

```bash
git revert --no-edit HEAD && git push
```

**이 명령은**: 방금 커밋을 반대로 되돌리는 커밋을 하나 더 만들어 올림(6단계에서 다시 자세히 봄).

| | 워크플로 없음 (지금) | 워크플로 있음 (3~6단계) |
|---|---|---|
| push | 그냥 올라감 | 올라간 뒤 바로 테스트 실행 |
| Actions 탭 · `gh run list` | 비어 있음 (`no runs found`) | 실행이 생김 — 깨지면 빨간 X |
| 테스트한 사람 | 없음 — 각자 기억에 맡김 | 러너가 push마다 |

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `nothing to commit, working tree clean` | sed가 바꾼 것이 없음(이미 100이거나 줄이 다름) | `grep -n MAX_TITLE api/todo.js` — 2번째 줄이 `const MAX_TITLE = 200;`이어야 함 |
| `gh run list`에 실행이 보임 | 이미 `.github/workflows`에 파일이 있음(실습 3을 다시 하는 경우) | 정상 — 이 단계는 처음 할 때만 의미가 있음. revert만 하고 넘어감 |

</details>

## 2단계. 올리기 전에 받아 보기

나중에 이미지를 받을 주소로 지금 받아 봅니다. `<아이디>`는 내 GitHub 아이디(**소문자**)로 바꿉니다.

```bash
docker pull ghcr.io/<아이디>/cicd-lab/api:main
```

**이 명령은**: GitHub의 레지스트리(`ghcr.io`)에서 내 저장소의 api 이미지를 받음. Docker Hub에서 받던 `docker pull`과 같습니다.

**이렇게 나오면 성공** — 받지 못하고 실패합니다(이 단계는 실패하는 것이 맞습니다)

```
Error response from daemon: error from registry: denied
denied
```

- 아직 아무도 이미지를 만들어 올리지 않았습니다. Docker 과목에서는 내가 `docker build`·`docker push`를 손으로 했습니다

| | 올리지 않으면 (지금) | 워크플로가 올리면 (3~7단계) |
|---|---|---|
| 이미지가 있는 곳 | 없음 | `ghcr.io/<아이디>/cicd-lab/api` |
| 다른 VM · 클러스터 | 받을 수 없음 (`denied`) | `docker pull`로 받음 |
| 어떤 코드로 만들었나 | — | `:<커밋 SHA>` 태그 — 커밋 하나에 이미지 하나 |

## 3단계. 워크플로 파일 쓰기

```bash
cd ~/cicd-lab
mkdir -p .github/workflows && nano .github/workflows/api.yml
```

아래를 붙여 넣고 **Ctrl+O → Enter → Ctrl+X**. 들여쓰기는 스페이스 2칸입니다.

```yaml
name: api

on:
  push:
    branches: [main]
    paths:
      - "api/**"
      - ".github/workflows/api.yml"
  workflow_dispatch:

permissions:
  contents: read
  packages: write          # GHCR에 올리려면 필요

jobs:
  build:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v7

      - uses: actions/setup-node@v7
        with:
          node-version: 22

      - name: 테스트
        working-directory: api
        run: |
          npm ci
          npm test

      - name: 이미지 이름 (GHCR는 소문자만)
        id: img
        run: echo "name=ghcr.io/${GITHUB_REPOSITORY,,}/api" >> "$GITHUB_OUTPUT"

      - uses: docker/login-action@v4
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: 빌드·올리기
        uses: docker/build-push-action@v7
        with:
          context: api
          push: true
          tags: |
            ${{ steps.img.outputs.name }}:${{ github.sha }}
            ${{ steps.img.outputs.name }}:main
```

**이 파일은** — 언제(`on`) · 어디서(`runs-on`) · 무엇을(`steps`)

| 줄 | 뜻 |
|---|---|
| `on: push: branches: [main]` | main에 push하면 실행 |
| `paths:` | 이 경로(api 폴더, 이 워크플로 파일)가 바뀔 때만 실행 |
| `workflow_dispatch:` | Actions 화면의 버튼으로 손으로도 실행 가능 |
| `permissions: packages: write` | 이 실행이 GHCR에 올려도 됨 |
| `runs-on: ubuntu-24.04` | 러너 종류(Ubuntu 24.04 가상 머신) |
| `actions/checkout` · `actions/setup-node` | 내 저장소 파일을 러너로 받음 · Node 22 설치 |
| `테스트` | api 폴더에서 `npm ci`(라이브러리 설치) → `npm test`(테스트) |
| `이미지 이름` | `ghcr.io/<아이디>/cicd-lab/api`를 만듦. GHCR 이름은 **소문자만** 되므로 `,,`(소문자로 바꾸기) |
| `docker/login-action` | GHCR에 로그인. 비밀번호 자리의 `GITHUB_TOKEN`은 실행할 때마다 GitHub가 새로 만들어 주는 임시 토큰 — 저장소에 비밀번호를 넣지 않아도 됨 |
| `빌드·올리기` | `docker build` + `docker push`. 태그 두 개 |

| 태그 | 쓰임 |
|---|---|
| `:<커밋 SHA>` | 정확히 이 커밋으로 만든 이미지 — 배포에 사용 |
| `:main` | main의 가장 최근 — 사람이 보기 편하게 |

## 4단계. 올리고 실행 지켜보기

```bash
git add . && git commit -m "ci: api 첫 워크플로" && git push
gh run watch
```

**이 명령은**: 새 파일이라 `git add`가 필요합니다(`commit -a`로는 안 들어감). `gh run watch` = 방금 시작된 실행을 터미널에서 지켜보기. 브라우저로는 내 저장소의 **Actions** 탭에서 봅니다.

**이렇게 나오면 성공**: Actions 탭에 `api` 실행이 생기고, 30초쯤 뒤 초록 체크. `build` job을 누르면 단계 목록에 `테스트`, `이미지 이름 (GHCR는 소문자만)`, `빌드·올리기`가 모두 초록입니다. `테스트` 단계를 펼치면 끝에 이렇게 보입니다.

```
ok 3 - 제목은 200자까지 남긴다
…
# tests 3
# pass 3
# fail 0
```

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `refusing to allow an OAuth App to create or update workflow ... without workflow scope` | 토큰에 `workflow` 권한이 없음 | 실습 1의 2단계로 토큰을 새로 만들어 `gh auth login --with-token` 다시 |
| Actions 탭에 아무것도 안 뜸 | 폴더 이름 오타(`.github/workflow`) 또는 들여쓰기가 틀려 워크플로를 읽지 못함 | `ls .github/workflows` 확인. Actions 탭의 빨간 경고를 봄. 스페이스 2칸, 탭 금지 — 파일을 지우고 다시 붙여 넣기 |
| `found no in progress runs to watch` | push 직후라 실행이 아직 만들어지지 않음 | 몇 초 뒤 `gh run watch` 다시 |
| `? Select a workflow run` 목록이 나옴 | 지켜볼 실행을 고르라는 것 | 맨 위(방금 push한 것)에서 Enter |
| `빌드·올리기`에서 `denied`·`403` | `permissions:`의 `packages: write`가 빠짐 | 3단계 파일과 비교 |

</details>

## 5단계. 일부러 테스트 깨뜨리기

1단계와 같은 변경을 이번에는 워크플로가 있는 상태로 올립니다. 테스트는 200을 기대하므로 실패해야 맞습니다.

```bash
sed -i 's/MAX_TITLE = 200/MAX_TITLE = 100/' api/todo.js
git commit -am "제목 100자로 줄임" && git push && gh run watch
```

**이렇게 나오면 성공** — `테스트` 단계에서 실패하고, 이미지 이름·로그인·빌드·올리기는 건너뜁니다(이 단계는 실패하는 것이 맞습니다)

```
not ok 3 - 제목은 200자까지 남긴다
  …
  error: |-
    Expected values to be strictly equal:

    100 !== 200
…
# pass 2
# fail 1
##[error]Process completed with exit code 1.
```

- 테스트가 막아 주지 않았다면 잘못된 코드가 그대로 이미지로 만들어져 레지스트리에 올라갔을 것입니다

## 6단계. 되돌리기 — git revert

```bash
git revert --no-edit HEAD && git push
gh run watch
git log --oneline -3
```

**이 명령은**: `git revert HEAD` = 마지막 커밋을 **지우지 않고**, 반대로 되돌리는 커밋을 하나 더 만듦. 기록이 남아서 누가 무엇을 되돌렸는지 알 수 있습니다. `--no-edit` = 메시지를 자동으로.

**이렇게 나오면 성공**: 새 실행이 다시 초록이고, 기록은 이렇습니다.

```
aaec0ca Revert "제목 100자로 줄임"
6a1a71b 제목 100자로 줄임
5163e4d ci: api 첫 워크플로
```

## 7단계. Packages 확인하고 VM에서 받기

1. 브라우저: 내 저장소 첫 화면 오른쪽 **Packages**에 `cicd-lab/api`가 보입니다(눌러 보면 태그 `main`과 긴 커밋 번호)
2. VM에서 2단계와 같은 주소로 받습니다.

```bash
docker pull ghcr.io/<아이디>/cicd-lab/api:main
docker image inspect ghcr.io/<아이디>/cicd-lab/api:main --format '{{.Config.User}}'
```

**이 명령은**: 2단계에서 `denied`였던 바로 그 명령. `docker image inspect … {{.Config.User}}` = 이 이미지가 어느 사용자로 도는지(보안 실습 3의 `USER 1000`).

**이렇게 나오면 성공**

```
Status: Downloaded newer image for ghcr.io/<아이디>/cicd-lab/api:main
ghcr.io/<아이디>/cicd-lab/api:main
1000
```

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `error from registry: denied` | 주소 오타(`<아이디>`·`cicd-lab`) 또는 아직 안 올라감 — 없는 패키지에도 GHCR는 `denied`로 답함 | Actions 실행이 초록인지, 주소 글자 확인. 저장소가 Private이면 패키지도 비공개 → 저장소를 Public으로 |
| `invalid reference format: repository name (…) must be lowercase` | 주소에 대문자 | 모두 소문자로 |

</details>

## 끝났는지 확인
- ☐ 1단계에서 `gh run list`가 `no runs found`(워크플로 없음)
- ☐ 2단계 `docker pull`이 `denied`
- ☐ 5단계 실행이 `not ok 3 - 제목은 200자까지 남긴다`로 빨간 X
- ☐ 되돌린 뒤 가장 최근 `api` 실행이 초록
- ☐ VM에서 `docker pull ghcr.io/<아이디>/cicd-lab/api:main` 성공

## 정리
- 지울 것 없음. `.github/workflows/api.yml`을 실습 4에서 고쳐 씁니다
