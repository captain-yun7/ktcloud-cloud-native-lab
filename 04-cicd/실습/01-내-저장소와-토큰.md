# 실습 1. 내 저장소와 토큰

**무엇을 하나요**: 템플릿으로 내 GitHub 공개 저장소 `cicd-lab`을 만들고, 토큰을 만들어 VM에서 GitHub에 로그인한 뒤 저장소를 VM으로 받습니다. 과목 내내 이 저장소 하나를 씁니다. 안에는 앞 과목에서 쓴 todo 앱(api · web · db)이 들어 있습니다. (교안 02장)

**필요한 것**: GitHub 계정, 서버 VM 접속.

> **바로 가기** · [1. 템플릿으로 내 저장소 만들기 (브라우저)](#1단계-템플릿으로-내-저장소-만들기-브라우저) · [2. 토큰 만들기 (브라우저)](#2단계-토큰-만들기-브라우저) · [3. 도구 받기](#3단계-도구-받기) · [4. 토큰으로 로그인](#4단계-토큰으로-로그인) · [5. 저장소 받기와 내 이름 설정](#5단계-저장소-받기와-내-이름-설정) · [끝났는지 확인](#끝났는지-확인) · [정리](#정리) · [확인 문제](#확인-문제)

## 1단계. 템플릿으로 내 저장소 만들기 (브라우저)

1. 브라우저에서 `https://github.com/captain-yun7/ktcloud-cicd-template` 열기
2. 오른쪽 위 초록 버튼 **Use this template → Create a new repository**
3. Owner = 본인 계정, Repository name = `cicd-lab`, **Public** 선택 → 맨 아래 **Create repository**

**이렇게 나오면 성공**: 주소가 `https://github.com/<아이디>/cicd-lab`이고, 파일 목록에 `api`, `deploy`, `web`, `README.md`가 보입니다.

- **Public**이어야 합니다. 실습 3에서 로그인 없이 이미지를 받고, 실습 6에서 Argo CD가 비밀번호 없이 저장소를 읽습니다

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| **Use this template** 버튼이 없음 | GitHub에 로그인하지 않음 | 오른쪽 위 Sign in 후 다시 |
| 같은 이름의 저장소가 이미 있다는 경고 | 예전에 `cicd-lab`을 만든 적 있음 | 예전 저장소의 이름을 바꾸거나 지운 뒤 다시. 명령이 `cicd-lab` 기준이라 이름을 맞춥니다 |
| Private으로 만듦 | 선택 실수 | 저장소 **Settings → General** 맨 아래 **Danger Zone → Change visibility → Public** |

</details>

## 2단계. 토큰 만들기 (브라우저)

1. GitHub 오른쪽 위 **프로필 사진 → Settings**
2. 왼쪽 메뉴 맨 아래 **Developer settings → Personal access tokens → Tokens (classic)**
3. **Generate new token → Generate new token (classic)**
4. 아래 표대로 적고 맨 아래 **Generate token**
5. 화면에 한 번만 보이는 토큰(`ghp_…`)을 복사해 둡니다(다음 단계에서 바로 씀)

| 항목 | 값 |
|---|---|
| Note | `ktcloud-lab` |
| Expiration | 30 days |
| 권한 (체크) | `repo`, `workflow`, `write:packages`, `read:org` |

| 권한 | 왜 필요한가 |
|---|---|
| `repo` | 저장소 읽기·쓰기 |
| `workflow` | `.github/workflows/` 파일을 push할 때 (실습 3) |
| `write:packages` | Jenkins가 GHCR에 이미지를 올릴 때 (실습 5) |
| `read:org` | `gh` 로그인에 필요 |

- 토큰은 **비밀번호와 같습니다**([시작하기 전에 5](./00-시작하기-전에.md#5-github-계정과-토큰--비밀번호처럼)). 실습 5에서 한 번 더 씁니다

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| Developer settings가 안 보임 | 저장소의 Settings로 들어감 | 오른쪽 위 **프로필 사진** → Settings(계정 설정) |
| 토큰을 복사하기 전에 화면을 벗어남 | 토큰은 만든 직후 한 번만 보임 | 그 토큰을 지우고(Delete) 새로 만듦 |
| Fine-grained tokens 화면에서 만듦 | 메뉴 선택 실수 | **Tokens (classic)** 에서 다시 |

</details>

## 3단계. 도구 받기

```bash
cd ~/ktcloud-cloud-native-lab && git pull && cd lab && make tools
source ~/.bashrc
```

**이 명령은**: 수업 저장소를 최신으로 받고(`git pull`), `make tools`로 이 과목에 쓰는 도구 `gh`(GitHub 명령줄 도구)·`argocd`를 설치합니다. `source ~/.bashrc`는 새로 설치한 도구를 지금 터미널에서 바로 쓰게 합니다.

**이렇게 나오면 성공**: 오류 없이 끝나고, `gh --version`이 `gh version 2.101.0`으로 시작합니다.

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `make: *** No rule to make target 'tools'.` | `lab` 폴더가 아닌 곳에서 실행 | `cd ~/ktcloud-cloud-native-lab/lab` 후 `make tools` |
| (다음 단계에서) `gh: command not found` | `source ~/.bashrc`를 빠뜨림 | `source ~/.bashrc` 또는 터미널을 새로 열기 |

</details>

## 4단계. 토큰으로 로그인

```bash
gh auth login --with-token          # 토큰을 붙여 넣고 Enter, Ctrl+D
gh auth setup-git                   # git push가 이 토큰을 쓰도록
gh auth status
```

**이 명령은**
- `gh auth login --with-token` = 붙여 넣은 토큰으로 GitHub에 로그인. 명령을 치면 아무 안내 없이 기다립니다 → 토큰 붙여 넣기 → **Enter** → **Ctrl+D**(입력 끝)
- `gh auth setup-git` = 앞으로 `git push`할 때 이 토큰을 쓰게 함(매번 비밀번호를 묻지 않음)
- `gh auth status` = 로그인 상태 보기

**이렇게 나오면 성공**

```
github.com
  ✓ Logged in to github.com account <아이디> (/home/lab/.config/gh/hosts.yml)
  - Active account: true
  - Git operations protocol: https
```

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| 붙여 넣은 뒤 아무 반응 없음 | Ctrl+D를 누르지 않음 | Enter → Ctrl+D |
| `read:org` 권한이 없다는 오류 | 토큰에 `read:org`가 빠짐 | 2단계로 토큰을 새로 만들어 다시 로그인 |
| (실습 2) `git push`가 `Username for 'https://github.com':`을 물음 | `gh auth setup-git`을 빠뜨림 | Ctrl+C → `gh auth setup-git` → 다시 push |

</details>

## 5단계. 저장소 받기와 내 이름 설정

```bash
cd ~ && gh repo clone <아이디>/cicd-lab && cd cicd-lab
git config --global user.name "<이름>"; git config --global user.email "<GitHub 이메일>"
ls
```

**이 명령은**: GitHub의 내 저장소를 VM의 `~/cicd-lab` 폴더로 받습니다(clone = 복제). `git config`는 커밋에 남을 내 이름·이메일을 정합니다(한 번만 하면 됨).

**이렇게 나오면 성공**

```
Cloning into 'cicd-lab'...
api  deploy  README.md  web
```

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `GraphQL: Could not resolve to a Repository` 비슷한 오류 | `<아이디>`를 안 바꿨거나 저장소 이름이 다름 | 브라우저 주소의 아이디·이름 그대로 |
| (실습 2에서 커밋할 때) `Author identity unknown ... Please tell me who you are.` | `git config` 줄을 실행하지 않음 | 위 `git config` 줄을 실행하고 다시 커밋 |

</details>

## 끝났는지 확인
- ☐ GitHub에 `https://github.com/<아이디>/cicd-lab` 공개 저장소가 있다
- ☐ `gh auth status`에 `Logged in to github.com account <아이디>`
- ☐ `~/cicd-lab`에서 `ls`가 `api  deploy  README.md  web`

## 정리
- 지울 것 없음. `~/cicd-lab`과 토큰을 과목 끝까지 씁니다
