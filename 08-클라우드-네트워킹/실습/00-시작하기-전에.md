# 시작하기 전에

실습 1을 시작하기 전에 한 번 읽어 주세요. 접속·붙여넣기는 앞 과목과 같습니다. 자세한 설명은 [Kubernetes 실습 문서의 시작하기 전에](../../02-kubernetes/실습/00-시작하기-전에.md)에 있습니다.

이 과목은 AWS를 다루기 전에 회사 전산실·사내망에서 쓰는 네트워크 기초를 배웁니다. 실습 5개와 미션 1개입니다.

| 순서 | 내용 |
|---|---|
| 실습 1 | DNS · TCP · TLS · HTTP |
| 실습 2 | VM의 IP 주소와 경로 확인 — 주소 · 서브넷 · 기본 게이트웨이 · NAT |
| 실습 3 | 리눅스로 라우터와 NAT 만들기 |
| 실습 4 | 서버 방화벽 대 라우터 ACL |
| 실습 5 | 로드밸런서와 헬스 체크 |
| 미션 | 네트워크 장애 해결 |

AWS에서 부르는 이름은 각 실습 끝의 **클라우드에서는**에 짧게 적어 두었습니다.

## 1. 서버에 접속하고, 명령은 VM 터미널에

- 접속: `ssh ktc-sNN` (`NN` = 본인 번호 두 자리). 절차와 오류 대처는 [접속 안내](../../00-접속-안내.md)
- **이 문서의 명령은 전부 서버 VM의 터미널에 칩니다.** 터미널 맨 앞이 `lab@sNN:~$`이면 서버 VM입니다
- 회색 코드 블록의 복사 버튼 → 터미널에 붙여 넣기. `#` 뒤는 설명이라 같이 붙여 넣어도 실행되지 않습니다
- `<db 파드 주소>`처럼 꺾쇠로 감싼 부분은 본인 값으로 바꾸고 꺾쇠도 지웁니다
- `sudo`가 비밀번호를 물으면 VM 비밀번호를 넣습니다(화면에 안 보이는 것이 정상)

**실습 1·2는 지금 VM과 클러스터를 그대로 읽습니다.** API Gateway 과목이 끝난 클러스터(노드 3개, todo, shop, 입구 80·8080)입니다. 아래 두 줄로 확인합니다.

```bash
kubectl get nodes
docker port lab-control-plane
```

**이렇게 나오면 성공**: 노드 3개 `Ready`, 포트 줄에 `80/tcp -> 0.0.0.0:80`과 `30080/tcp -> 0.0.0.0:8080`. 다르게 나오면 실습 2의 각 단계 **이렇게 나오면?** 표를 봅니다(바뀐 값 그대로 표를 채우면 됩니다).

**실습 3~5는 클러스터를 건드리지 않습니다.** VM 안에 따로 작은 사내망(라우터 · 웹 서버 · DB 서버)을 만들었다 지웁니다. 스크립트 이름에 들어 있는 `vpc`(`vpc-up.sh`, `vpc-down.sh` 등)는 **사내망**이라는 뜻입니다.

## 2. 줄임말 `web` · `db` · `rt` — 새 터미널마다 다시

실습 3부터 `web curl …`처럼 씁니다. `web` = "네임스페이스 web 안에서 실행"의 줄임말(alias)입니다. 실습 3의 2단계에서 만듭니다.

```bash
alias web="sudo ip netns exec web" db="sudo ip netns exec db" rt="sudo ip netns exec rt"
```

- 줄임말은 **그 터미널에만** 남습니다. 터미널을 새로 열었거나 다시 접속했으면 위 한 줄을 다시 칩니다
- `web: command not found`가 나오면 이 줄을 안 친 것입니다
- 실습 5는 `webb`(web-b 안에서)를 더 만듭니다. 그 실습 1단계에 줄이 있습니다

## 3. 출력이 문서와 조금 달라도 되는 것

| 달라도 되는 것 | 예 |
|---|---|
| VM 주소 | `10.10.1.23` 자리(사람마다 `10.10.1.N`) |
| 파드 주소 · Service 주소 · 브리지 이름 | `10.244.2.11`, `10.96.103.189`, `br-00f6611cf1e1` |
| 시간 | ping의 `time=0.05 ms`, tcpdump 맨 앞 시각 |
| 포트 번호(출발 쪽) | tcpdump의 `10.0.2.10.41442`의 `41442` |
| 숫자가 조금 다른 것 | 실습 5의 `10/20`이 `9/20`·`11/20`, 실습 1의 시간(`0.032`초 등) |
| 이름이 가리키는 주소 · TTL | 실습 1의 `example.com` 주소(`104.20.23.154` 등)와 `300` 같은 TTL 숫자 — 사이트가 바꾸면 달라짐 |

## 4. 막히면 — 질문하는 법

1. 에러의 **첫 줄**을 읽고, 그 단계의 **이렇게 나오면?** 표와 [자주 만나는 오류 한눈에](./99-자주-쓴-명령과-오류.md#자주-만나는-오류-한눈에)에서 같은 문구를 찾아봅니다
2. 실습 3~5가 꼬였으면 처음부터: `sudo bash ~/ktcloud-cloud-native-lab/lab/network/vpc-down.sh` → 그 실습의 시작 상태부터 다시. 사내망은 몇 초 만에 다시 만들어집니다
3. 그래도 모르겠으면 Discord에 질문합니다. 에러는 **사진이 아니라 글자로** 붙이고 아래 네 가지를 적습니다

```
[실습 3 - 5단계] (몇 번 실습, 몇 단계)
한 일: sudo iptables -t nat -A POSTROUTING ...
기대: db curl ... 에 301
실제: 000
해 본 것: (그대로 붙여넣기)
```

## 이 문서에 나오는 말

| 말 | 쉬운 뜻 |
|---|---|
| IP 주소 | 네트워크 안에서 컴퓨터를 찾는 번호. `10.0.1.10`처럼 점으로 나눈 숫자 4개 |
| CIDR · 대역 | 주소 묶음을 적는 방법. `10.0.0.0/16` = 앞 16비트가 같은 주소 전부(65,536개) |
| 사내망 | 회사 안에서만 쓰는 네트워크. 대역 하나(`10.0.0.0/16`)를 정해 만듦. 스크립트 이름의 `vpc`가 이것 |
| 서브넷 | 사내망을 작게 나눈 칸(`10.0.1.0/24`). 서버는 서브넷 하나에 놓임 |
| 라우터 · 라우팅 표(경로표) | 패킷을 다음 칸으로 넘겨 주는 장치 · "이 주소는 저쪽으로"라고 적은 표(`ip route`) |
| 기본 경로(default) · 기본 게이트웨이 | 표에 없는 모든 주소를 보낼 곳(`0.0.0.0/0`) · 그 줄의 `via` 주소(내 VM은 `10.10.0.1`) |
| 브리지 | 같은 칸의 컴퓨터(컨테이너)들을 잇는 가상 스위치. kind 노드들이 붙은 `br-…` |
| 인터넷 출구 | 사내망과 인터넷 사이의 문. 회사 공유기·방화벽 장비 자리 |
| 사설 주소 · 공인 주소 | 사설 = 안에서만 쓰는 주소(`10.x`, `172.16~31.x`, `192.168.x`). 공인 = 인터넷에서 찾을 수 있는 주소 |
| NAT | 주소 바꾸기. 나가는 패킷의 출발 주소를 바깥 주소로 바꾸고, 돌아온 답을 되돌려 줌. 집·회사 공유기가 하는 일 |
| 포트 포워딩(DNAT) | 공유기에서 포트를 열어 밖에서 온 요청을 안쪽 서버로 넘기기 |
| 웹 서브넷(DMZ) · DB 서브넷(내부망) | 밖에서 들어올 길이 있는 칸 · 나가기만 하고 들어올 길은 없는 칸 |
| 서버 방화벽 | 서버 자체에 거는 방화벽(iptables·ufw). 보낸 요청의 답은 자동 허용(상태 기억) |
| 라우터 ACL | 망 경계 라우터에 거는 규칙. 답도 따로 허용해야 함(상태 모름) |
| 서버 자리 a · b | 다른 랙·다른 전원에 나눠 둔 서버 자리. 한쪽이 꺼져도 다른 쪽이 받게 함 |
| 로드밸런서 · 헬스 체크 | 요청을 여러 서버에 나눠 보내는 입구 · 서버가 살아 있는지 확인하는 것 |
| DNS · 레코드 · TTL | 이름(`example.com`)을 주소로 바꿔 주는 시스템 · 그 안의 한 줄(A = 주소, CNAME = 다른 이름, NS = 이 이름을 맡은 서버) · 그 답을 기억해 둬도 되는 초 |
| TCP · 3-way handshake | 데이터를 빠짐없이 순서대로 주고받는 연결 · 연결을 맺는 인사 세 번(`[S]` → `[S.]` → `[.]`) |
| TLS · 인증서 | HTTPS의 S. 주고받는 내용을 암호화 · "이 서버가 진짜 `example.com`"이라는 증명서(발급자가 서명) |
| SNI | TLS 인사 때 "나는 `example.com`에 왔다"고 이름을 먼저 알려 주는 칸. 한 주소에 사이트가 여럿일 때 필요 |
| CoreDNS | 쿠버네티스 클러스터 안의 DNS. `web.todo.svc.cluster.local` 같은 이름을 Service 주소로 바꿈 |
| 네트워크 네임스페이스 | 리눅스 안에 따로 만든 작은 네트워크 공간. 실습 3~5에서 서버·라우터 역할 |
| veth | 네임스페이스 둘을 잇는 가상의 랜선. 양 끝이 한 쌍 |
| iptables | 리눅스의 방화벽·주소 바꾸기 규칙을 넣는 명령 |

**curl 끝난 번호** — `echo "[$?]"`가 보여 주는 숫자

| 번호 | 뜻 | 이 과목에서 보는 때 |
|---|---|---|
| `[0]` | 성공 | 정상 |
| `[6]` | 이름을 주소로 못 바꿈 | DNS 서버가 틀림(미션) |
| `[7]` | 연결 거절 — 그 포트에 아무것도 없음 | 서버가 안 켜짐, DNAT 전(실습 3 6단계), 로드밸런서 뒤 서버 하나가 꺼짐(실습 5) |
| `[28]` | 시간 초과 — 답이 없음 | 길이 없음(실습 2 4단계), 방화벽이 버림(실습 4) |
| `[35]` · `[60]` | TLS 인사 실패 · 인증서의 이름이 틀림 | 이름 없이 주소로 HTTPS · 다른 이름으로 접속(실습 1 4단계) |
| `000` (`-w "%{http_code}"`) | 응답을 하나도 못 받음 | NAT 전(실습 3 4단계), 라우터 ACL 답 규칙 전(실습 4) |

## 만드는 사내망과 쓰는 대역 (실습 3~5)

```
            인터넷
              │  eth0 (VM 주소 = "공인 IP" 역할)
        ┌─────┴──────────────────┐
        │ VM = 인터넷 출구(공유기) │  igw 10.0.255.1
        └─────┬──────────────────┘
              │ 10.0.255.0/30
        ┌─────┴──────────┐
        │  rt (사내 라우터) │
        └──┬──────────┬──┘
 10.0.1.0/24│          │10.0.2.0/24
     ┌──────┴───┐  ┌───┴──────┐
     │ web      │  │ db       │
     │ 10.0.1.10│  │ 10.0.2.10│
     │ 웹(DMZ)  │  │ DB(내부망)│
     └──────────┘  └──────────┘
```

- 실습 5는 두 번째 웹 서브넷 `10.0.3.0/24`(서버 자리 b, 서버 `web-b` `10.0.3.10`)를 더 붙인 사내망에서 합니다

| 회사 망 부품 | 이 과목에서 (VM 안) |
|---|---|
| 사내망 | 네임스페이스 묶음 + 대역 `10.0.0.0/16` |
| 서브넷 | veth 선 하나 = `/24` 하나 |
| 라우터 · 라우팅 표 | `rt` · 각 네임스페이스의 `ip route` |
| 인터넷 출구 · NAT(공유기) · 포트 포워딩 | VM 자신 + `iptables -t nat` |
| 서버 방화벽 · 라우터 ACL | 서버 안의 `iptables` · 라우터의 `iptables` |
| 서버 자리 a · b | 서브넷으로 구분(`10.0.1.0/24` = a, `10.0.3.0/24` = b) |
| 로드밸런서 | VM의 9090번에 띄운 nginx 컨테이너 |

| 폴더 · 파일 | 무엇 |
|---|---|
| `~/ktcloud-cloud-native-lab/lab/network/vpc-up.sh` | 빈 사내망을 만듦(이름의 `vpc` = 사내망). `--routed`를 붙이면 실습 3이 끝난 상태(경로·NAT·web/db 서버, 포트 포워딩 제외), `--az2`를 붙이면 거기에 두 번째 웹 서브넷(`web-b`)까지 |
| `~/ktcloud-cloud-native-lab/lab/network/vpc-down.sh` | 이 과목이 만든 네임스페이스·규칙·LB 컨테이너를 모두 지움. 클러스터는 건드리지 않음 |
| `~/ktcloud-cloud-native-lab/lab/network/lb/nginx.conf` | 실습 5의 로드밸런서 설정 |
| `~/ktcloud-cloud-native-lab/lab/network/break-vpc.sh` · `vpc-check.sh` | 미션. 장애를 넣은 사내망을 만듦 · 다 고쳤는지 세 가지 확인 |
