# 자주 쓴 명령과 오류

## 자주 쓴 명령

- 이름·연결·TLS(실습 1): `dig 이름` · `dig +short 이름` · `curl -v` · `curl -s -o /dev/null -w "%{time_connect} %{time_appconnect}\n" 주소`
- 클러스터 안 이름(실습 1): `kubectl -n todo exec deploy/load -c curl -- nslookup 이름.네임스페이스.svc.cluster.local`
- 주소·길 보기: `ip -br addr` · `ip route` · `ip route get <주소>` · `ping -c N` · `tracepath -n` · `sudo tcpdump -lni eth0 …`
- 클러스터의 주소(실습 2): `ip -br addr show type bridge` · `kubectl get nodes -o wide` · `kubectl -n todo get pods -o wide` · `kubectl -n todo get svc`
- 네임스페이스 안에서: `sudo ip netns exec <이름> …`(줄임말 `web`·`db`·`rt`, 부록 B1은 `vpcb`·`vpcc`) · `sudo ip -n <이름> …` · `sudo ip netns pids <이름>`(안에서 도는 프로그램 — 빈 출력이면 서버 꺼짐)
- 길 넣기·빼기: `ip route add default via <라우터>` · `ip route add <대역> via <다음>` · `ip route del <대역>`
- 규칙: `iptables -t nat -A POSTROUTING … -j MASQUERADE`(NAT) · `… -j DNAT --to-destination`(들어오기) · `iptables -A INPUT`(서버 방화벽) · `-I 체인 번호`(끼워 넣기) · `-D`(한 줄 지우기) · `-F`(모두 지우기) · `-S` · `-L … -n --line-numbers`(보기)
- 확인: `curl -s -m 초 -o /dev/null -w "%{http_code}\n" 주소` · `curl -s -m 3 주소; echo "[$?]"`
- 대역 계산: `python3 - <<'PY' … ip.ip_network(…).overlaps(…) … PY`
- 양 세기(부록 B2): `sudo ip netns exec rt ip -s -h link show rt-igw`
- 사내망 스크립트(이름의 vpc = 사내망): `sudo bash vpc-up.sh [--routed]` · `sudo bash vpc-down.sh` · 부록 B1 `sudo bash vpc-peer.sh new <이름> <주소>` · `sudo bash vpc-peer.sh link <쪽1> <쪽2> <N>`
- 미션 1: `sudo bash break-vpc.sh [번호]` · `bash vpc-check.sh`

## 자주 만나는 오류 한눈에

| 화면 | 뜻 | 먼저 해 볼 것 |
|---|---|---|
| `[6]` (curl) · `Could not resolve host` | 이름을 주소로 못 바꿈 | `cat /etc/resolv.conf`(네임스페이스는 `db cat /etc/resolv.conf`) · `dig 이름` · `dig @8.8.8.8 이름` |
| `;; communications error … timed out` · `no servers could be reached` (dig) | DNS 서버에 못 닿음 | `@8.8.8.8`로도 안 되면 이름이 아니라 길 문제 |
| `[35]` · `[60]` (curl) | TLS 인사 실패 · 인증서 이름이 틀림 | 주소 대신 이름(`https://이름`)으로 접속했는지 |
| `connect: Network is unreachable` | 표에 길이 없음 | `ip route`에 `default via …`가 있는지, 상대 대역 줄이 있는지 |
| `000` (curl) | 응답을 못 받음 | 라우터 기본 경로, VM의 사내망 경로(`10.0.0.0/16`), NAT 규칙(실습 3) |
| `[28]` (curl) | 시간 초과 — 길이 없거나 방화벽이 버림 | 경로(`ip route get 주소`, 부록 B1 피어링은 **양쪽** 표), 서버 방화벽 규칙(`iptables -S`) |
| `[7]` / `Connection refused` | 그 포트에 아무것도 없음 | 서버가 켜져 있는지(`sudo ip netns pids web`), DNAT 규칙(`sudo iptables -t nat -S \| grep 9080`) |
| `RTNETLINK answers: File exists` | 이미 있음 | 그대로 진행 |
| `Error: Nexthop has invalid gateway.` | `via` 뒤 주소로 가는 선이 없음 | 주소 오타, 부록 B1이면 피어링 선을 놓았는지(`vpc-peer.sh link`) |
| `Cannot open network namespace` | 사내망(네임스페이스)이 없음 | `sudo bash vpc-up.sh` (실습 4·부록은 `--routed`) |
| `web: command not found` | 줄임말 없음(새 터미널) | [시작하기 전에 2](./00-시작하기-전에.md#2-줄임말-web--db--rt--새-터미널마다-다시) |
| `The connection to the server … was refused` (kubectl) | kind 노드가 멈춤 | `docker start lab-control-plane lab-worker lab-worker2` |
