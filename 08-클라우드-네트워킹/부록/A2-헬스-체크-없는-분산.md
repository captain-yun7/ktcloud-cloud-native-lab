# 부록 실습 A2. 헬스 체크 없는 분산

> **부록** — 본편 수업(실습 1~5 · 미션)에는 들어가지 않는 실습입니다. 부록 A1에서 직접 붙인 두 번째 AZ로, 실습 5의 9091 입구를 따로 자세히 봅니다. 실습 3·4와 같은 VPC 도구(`vpc-up.sh --routed`)를 씁니다.

**무엇을 하나요**: VM의 9091번으로 온 요청을 web·web-b에 **번갈아** 보냅니다. 그다음 AZ-a(web)를 멈추고, 상대가 살아 있는지 모르는 채 나눠 보내면 어떻게 되는지 셉니다. (교안 06장 · 부록 A)

**필요한 것**: 부록 A1이 끝난 상태(web·web-b 서버).

> **바로 가기** · [1. 번갈아 보내기](#1단계-번갈아-보내기) · [2. AZ-a 장애 만들기](#2단계-az-a-장애-만들기) · [3. 20번 불러 세기](#3단계-20번-불러-세기) · [끝났는지 확인](#끝났는지-확인) · [정리](#정리) · [확인 문제](#확인-문제)

## 1단계. 번갈아 보내기

```bash
VM=$(hostname -I | cut -d' ' -f1)
sudo iptables -t nat -A OUTPUT -d $VM -p tcp --dport 9091 -m statistic --mode nth --every 2 --packet 0 -j DNAT --to-destination 10.0.1.10:80
sudo iptables -t nat -A OUTPUT -d $VM -p tcp --dport 9091 -j DNAT --to-destination 10.0.3.10:80
for i in 1 2 3 4; do curl -s $VM:9091; done
```

**이 명령은**: 첫 규칙 = 2번에 한 번은 web으로, 둘째 규칙 = 나머지는 web-b로. 마지막 줄 = 4번 불러 보기.

**이렇게 나오면 성공**: `web 10.0.1.10`과 `web-b 10.0.3.10`이 번갈아 나옴.

## 2단계. AZ-a 장애 만들기

```bash
sudo ip netns pids web | xargs -r sudo kill
curl -s -m 2 10.0.1.10; echo "[$?]"
```

**이 명령은**: 네임스페이스 web 안에서 도는 프로그램(웹 서버)을 모두 끔. AZ-a가 멈춘 상황입니다.

**이렇게 나오면 성공**: 응답 없이 `[7]`(접속 실패).

## 3단계. 20번 불러 세기

```bash
ok(){ n=0; for i in $(seq 1 20); do [ "$(curl -s -m 2 -o /dev/null -w %{http_code} $1)" = 200 ] && n=$((n+1)); done; echo "$n/20"; }
ok $VM:9091
```

**이 명령은**: `ok` = 주소를 20번 불러 200(성공)이 몇 번인지 세는 작은 함수. 실습 5에서도 씁니다.

**이렇게 나오면 성공**

```
10/20
```

- 약 절반이 실패합니다. 나눠 보내는 쪽이 **web이 멈춘 것을 모르고** 계속 보내기 때문입니다
- 다중 AZ로 서버를 둘 두는 것만으로는 부족하고, **응답하는 서버로만 보내는 기능**이 필요합니다 → 실습 5

| 화면 | 원인 | 해결 |

| `20/20` | web이 안 꺼짐 | 2단계 다시, `curl -s -m 2 10.0.1.10`이 실패하는지 |

## 끝났는지 확인

- ☐ 번갈아 두 서버가 응답
- ☐ web을 끈 뒤 `ok $VM:9091`이 약 `10/20`


**이렇게 나오면 성공**: `정리 완료`. 9091 규칙과 web-b까지 지워집니다. 로드밸런서로 같은 장애를 `20/20`으로 만드는 것은 [실습 5](../실습/05-로드밸런서와-헬스-체크.md)입니다.
