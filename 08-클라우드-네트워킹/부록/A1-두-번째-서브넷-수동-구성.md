# 부록 실습 A1. 두 번째 서브넷 수동 구성

> **부록** — 본편 수업(실습 1~5 · 미션)에는 들어가지 않는 실습입니다. 실습 5가 `vpc-up.sh --az2` 한 줄로 만든 두 번째 AZ를 **명령 한 줄씩 직접** 붙여 보고 싶을 때 A1 → A2 순서로 합니다. 실습 3·4와 같은 VPC 도구(`vpc-up.sh --routed`)를 씁니다.

**무엇을 하나요**: 실습 3이 끝난 VPC를 다시 만들고, 먼저 **AZ가 하나뿐일 때** web이 멈추면 어떻게 되는지 봅니다. 그다음 다른 가용 영역(AZ-b)에 해당하는 서브넷 `10.0.3.0/24`를 새로 붙여 web과 같은 역할의 서버 `web-b`를 둡니다. 서브넷 하나를 직접 붙이는 순서를 봅니다. (교안 06장 · 부록 A)

**필요한 것**: `lab/network` 폴더. 앞 실습에서 무엇이 남아 있든 상관없습니다(1단계에서 지우고 다시 만듦).

## 1단계. 실습 3 끝 상태로 다시 만들기

```bash
cd ~/ktcloud-cloud-native-lab && git pull && cd lab/network
sudo bash vpc-down.sh
sudo bash vpc-up.sh --routed
alias web="sudo ip netns exec web" webb="sudo ip netns exec web-b" rt="sudo ip netns exec rt"
curl -s 10.0.1.10
```

**이 명령은**: `vpc-down.sh` = 이 과목이 만든 것을 모두 지움. `vpc-up.sh --routed` = 실습 3이 끝난 상태(라우팅·NAT·web·db 서버)로 다시 만듦. `webb` = 네임스페이스 web-b 줄임말.

**이렇게 나오면 성공**

```
web 10.0.1.10
```

## 2단계. AZ 하나뿐일 때 — web 멈춰 보기

지금 서버(web)는 AZ-a 한 곳에만 있습니다. AZ-a에 장애가 나면 어떻게 되는지 web을 멈춰 봅니다.

```bash
sudo ip netns pids web | xargs -r sudo kill
curl -s -m 2 10.0.1.10; echo "[$?]"
ok(){ n=0; for i in $(seq 1 20); do [ "$(curl -s -m 2 -o /dev/null -w %{http_code} $1)" = 200 ] && n=$((n+1)); done; echo "$n/20"; }
ok 10.0.1.10
```

**이 명령은**: 1줄 = 네임스페이스 web 안에서 도는 프로그램(웹 서버)을 모두 끔 = AZ-a 장애. 2줄 = web에 접속. 3줄 = `ok` = 주소를 20번 불러 200(성공)이 몇 번인지 세는 작은 함수(부록 A2·A3에서도 씀). 4줄 = web을 20번.

**이렇게 나오면 성공** (실패하는 것이 맞음)

```
[7]
0/20
```

- `7` = 접속 실패. 서버가 한 곳뿐이라 **20번 모두 실패**합니다. 다른 곳으로 보낼 서버가 없습니다

web을 다시 켭니다.

```bash
web sh -c 'cd /tmp/vpc-web && nohup python3 -m http.server 80 >/dev/null 2>&1 &'
sleep 1; curl -s 10.0.1.10
```

**이렇게 나오면 성공**

```
web 10.0.1.10
```

| 화면 | 원인 | 해결 |
|---|---|---|
| `20/20` | web이 안 꺼짐 | 첫 줄 다시, `sudo ip netns pids web`이 빈 출력인지 |
| `can't cd to /tmp/vpc-web` 류 | 1단계를 `--routed` 없이 함 | 1단계 다시 |
| 다시 켠 뒤에도 빈 출력 | 서버가 뜨기 전에 부름 | `curl -s 10.0.1.10` 한 번 더 |

</details>

## 3단계. AZ-b 서브넷 붙이기

```bash
sudo ip netns add web-b && sudo ip -n web-b link set lo up
sudo ip link add rt-webb type veth peer name webb0
sudo ip link set rt-webb netns rt && sudo ip link set webb0 netns web-b
sudo ip -n rt    addr add 10.0.3.1/24  dev rt-webb && sudo ip -n rt    link set rt-webb up
sudo ip -n web-b addr add 10.0.3.10/24 dev webb0   && sudo ip -n web-b link set webb0 up
sudo ip -n web-b route add default via 10.0.3.1
```

**이 명령은** (줄마다)

| 줄 | 하는 일 | 클라우드에서 |
|---|---|---|
| 1 | 네임스페이스 web-b 만들기 | 서버 한 대 |
| 2 | 선(veth) 한 쌍 `rt-webb` ↔ `webb0` | 서브넷 하나 |
| 3 | 한쪽 끝은 라우터에, 한쪽 끝은 web-b에 | 서브넷을 VPC 라우터에 연결 |
| 4·5 | 양쪽에 주소, 켜기(up) | 서브넷 `10.0.3.0/24` |
| 6 | web-b의 기본 경로 = 라우터 | 라우팅 테이블 |

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `Cannot create namespace … File exists` | 이미 만듦 | 1단계부터 다시(`vpc-down.sh`) |
| `Cannot find device "rt-webb"` | 2번째 줄을 빠뜨림 | 1단계부터 다시 |

</details>

## 4단계. web-b 서버 켜기

```bash
webb sh -c 'mkdir -p /tmp/vpc-web-b && echo "web-b 10.0.3.10" > /tmp/vpc-web-b/index.html && cd /tmp/vpc-web-b && nohup python3 -m http.server 80 >/dev/null 2>&1 &'
curl -s 10.0.3.10
```

**이렇게 나오면 성공**

```
web-b 10.0.3.10
```

```
        ┌──────────── VPC 10.0.0.0/16 ────────────┐
        │  AZ-a                   AZ-b             │
        │  10.0.1.0/24 web        10.0.3.0/24 web-b│
        │  10.0.2.0/24 db                          │
        └──────────────────────────────────────────┘
```

- 실제 클라우드에서 서브넷은 AZ 하나에 속합니다. 여기서는 서브넷 이름으로 AZ를 구분합니다

## 끝났는지 확인

- ☐ `curl -s 10.0.1.10` → `web 10.0.1.10`
- ☐ AZ 하나뿐일 때 web을 멈추면 `0/20`, 다시 켜서 `web 10.0.1.10`
- ☐ `curl -s 10.0.3.10` → `web-b 10.0.3.10`
