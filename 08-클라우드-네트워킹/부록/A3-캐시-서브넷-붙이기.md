# 부록 실습 A3. 캐시 서브넷 붙이기

> **부록** — 본편 수업(실습 1~5 · 미션)에는 들어가지 않는 실습입니다. 미션을 일찍 마쳤을 때 합니다.

**무엇을 하나요**: 실습 3·4에서 만든 것과 같은 VPC에 새 프라이빗 서브넷 `10.0.4.0/24`를 만들고 캐시 서버 `cache`(`10.0.4.10`, 6379번)를 붙입니다. 부록 B3 과제 4에서 표로 적은 cache-sg를 직접 만들어 보는 실습입니다. 선 잇기 · 기본 경로 · NAT · 보안그룹을 직접 조합합니다.

**필요한 것**: 실습 3·4. (해 봤다면) 부록 B3 과제 4의 보안그룹 표.

**시작 상태**: 실습 3이 끝난 VPC. 아래 세 줄로 만듭니다.

```bash
cd ~/ktcloud-cloud-native-lab/lab/network
sudo bash vpc-up.sh --routed
alias web="sudo ip netns exec web" db="sudo ip netns exec db" rt="sudo ip netns exec rt"
```

| 할 일 | 이렇게 나오면 성공 |
|---|---|
| 1. 네임스페이스 `cache`, 라우터 `rt`와 잇는 선, 주소(rt 쪽 `10.0.4.1/24`, cache 쪽 `10.0.4.10/24`), cache의 기본 경로 | `web ping -c1 10.0.4.10` → `ttl=63` |
| 2. cache 안에서 6379번 서버 | `web curl -s 10.0.4.10:6379` → `cache 10.0.4.10` |
| 3. cache에 보안그룹 — web 서브넷에서 6379만 | web → cache 응답, `db curl -s -m 3 10.0.4.10:6379; echo "[$?]"` → `[28]` |
| 4. cache에서 인터넷으로 | `sudo ip netns exec cache curl -s -m 4 -o /dev/null -w "%{http_code}\n" http://1.1.1.1` → `301` |

<details><summary>힌트 1 — 선 잇기</summary>

`vpc-up.sh`를 열어 보면 선 만드는 순서가 있습니다: `ip netns add` → `ip link add <이름> type veth peer name <이름>` → 한쪽을 `rt`, 한쪽을 `cache`로 `ip link set … netns …` → 양쪽에 주소와 `up`. 줄마다 `sudo`.
</details>

<details><summary>힌트 2 — 서버와 보안그룹</summary>

서버는 실습 3 6단계의 db 줄에서 폴더·글·포트만 바꿉니다(`python3 -m http.server 6379`). 보안그룹은 실습 4 2단계의 세 줄에서 `db` 대신 cache 안에서(`sudo ip netns exec cache iptables …`), `5432` 대신 `6379`.
</details>

<details><summary>힌트 3 — 인터넷</summary>

새 규칙이 필요할까요? 실습 3 5단계의 NAT 규칙이 어떤 대역을 덮는지 보세요(`-s 10.0.0.0/16`).
</details>

## 정리

```bash
sudo bash ~/ktcloud-cloud-native-lab/lab/network/vpc-down.sh
```

**이렇게 나오면 성공**: `정리 완료` — cache까지 모두 지웁니다.
