# 미션 1. 네트워크 장애 해결

**무엇을 하나요**: 사내망에 장애가 났다고 합시다. 실습 3·4에서 만든 VM 안 사내망(web · db · 라우터 · NAT · 9080 포트 포워딩)에 **스크립트가 고장을 섞어 넣습니다.** 층마다(DNS · 라우팅 · 포트 · 방화벽 · 앱) 고장이 하나씩 있고, 모두 실습에서 직접 넣어 본 줄이 빠지거나 틀린 것입니다. 과제 2의 **층별 점검표**를 위에서부터 한 칸씩 쳐 보고, 정상 출력과 다른 줄을 실습 문서의 명령으로 다시 넣어 확인 세 줄을 모두 ✔로 만듭니다. 목표: `bash vpc-check.sh`의 마지막 줄 `3/3`.

**필요한 것**

| 확인할 것 | 내용 |
|---|---|
| VM | 실습 3·4를 해 본 학생 VM. 사내망은 스크립트가 새로 만들어 줍니다(지금 있는 사내망은 지우고 다시 만듦) |
| 스크립트 | 학생 저장소의 `lab/network/break-vpc.sh`(장애를 넣은 사내망 만들기) · `vpc-check.sh`(세 가지 확인, 원인은 알려 주지 않음) |
| 명령 | 새 명령 없음 — 점검표의 명령은 모두 실습 3·4에서 쓴 것(`cat /etc/resolv.conf` · `ip route` · `iptables -S` · `curl`) |
| 끝나면 | `sudo bash ~/ktcloud-cloud-native-lab/lab/network/vpc-down.sh`(클러스터는 그대로) |

> **바로 가기** · [과제 1. 고장 만들고 증상 보기](#과제-1-고장-만들고-증상-보기) · [과제 2. 층별 점검표로 찾아 고치기](#과제-2-층별-점검표로-찾아-고치기) · [과제 3. 결과 정리](#과제-3-결과-정리) · [결과 정리 표](#결과-정리-표)

## 과제 1. 고장 만들고 증상 보기

장애를 넣은 사내망을 만들고, 확인 세 줄의 화면을 적어 둡니다. 아직 고치지 않습니다.

```bash
cd ~/ktcloud-cloud-native-lab && git pull && cd lab/network
sudo bash break-vpc.sh
alias web="sudo ip netns exec web" db="sudo ip netns exec db" rt="sudo ip netns exec rt"
bash vpc-check.sh
```

**처음 화면 예** (사람마다 고장이 달라 ✘ 뒤 번호가 다를 수 있음)

```
고장 난 VPC 준비 완료 (문제 번호 2 — 같은 문제를 다시 풀려면 sudo bash break-vpc.sh 2)
층마다(DNS · 라우팅 · 포트 · 방화벽 · 앱) 고장이 하나씩 있습니다. 확인: bash vpc-check.sh
✘ ① db → https://example.com   000 [28]
✘ ② web → db 5432             [7]
✘ ③ VM → 10.10.1.23:9080 (web)   [7]
0/3
```

| 확인 | 뜻 | 정상이면 |
|---|---|---|
| ① | DB 서브넷(내부망)의 db가 이름으로 인터넷(HTTPS)에 나감 | `200` |
| ② | 웹 서브넷의 web이 db의 5432에 닿음 | `db 10.0.2.10` |
| ③ | 밖(VM)에서 포트 포워딩 9080으로 web에 들어옴 | `web 10.0.1.10` |

- 첫 줄의 **문제 번호**를 결과 정리 표에 적습니다. 같은 번호면 같은 고장이라 처음부터 다시 할 수 있습니다
- 확인 줄마다 ✘ 뒤의 번호(`000 [28]`, `[7]` 등)를 그대로 적습니다. 어느 층의 고장인지는 과제 2의 점검표로 찾습니다

**이렇게 나오면 성공**: 마지막 줄이 `0/3`(또는 `1/3`처럼 일부만 ✘)이고, 문제 번호와 ✘ 줄의 번호를 결과 정리 표에 적었음.

## 과제 2. 층별 점검표로 찾아 고치기

과제 1에서 본 화면과 상관없이 **점검표 1번부터 차례로** 칩니다. 칸마다 "정상이면" 칸과 화면을 글자로 비교합니다. 같으면 다음 칸으로, 다르면 "다르면 다시 넣을 줄"을 치고 다음 칸으로 갑니다. 층 하나(DNS · 라우팅 · 포트 · 방화벽 · 앱)를 끝낼 때마다 `bash vpc-check.sh`를 다시 칩니다.

**층별 점검표**

| 순서 | 층 | 확인 명령 | 정상이면 | 다르면 다시 넣을 줄 |
|---|---|---|---|---|
| 1 | DNS | `db cat /etc/resolv.conf` | `nameserver 8.8.8.8` (실습 3 3단계 나.의 출력과 같음) | `echo "nameserver 8.8.8.8" \| sudo tee /etc/netns/db/resolv.conf` — 실습 3 3단계 나.에서 본 파일을 이 한 줄로 되돌림 |
| 2 | 라우팅 | `db ip route` | `default via 10.0.2.1 dev db0`<br>`10.0.2.0/24 dev db0 proto kernel scope link src 10.0.2.10` | `sudo ip -n db route add default via 10.0.2.1` (실습 3 2단계 나.) |
| 3 | 라우팅 | `rt ip route` | `default via 10.0.255.1 dev rt-igw`<br>`10.0.1.0/24 dev rt-web proto kernel scope link src 10.0.1.1`<br>`10.0.2.0/24 dev rt-db proto kernel scope link src 10.0.2.1`<br>`10.0.255.0/30 dev rt-igw proto kernel scope link src 10.0.255.2` | `sudo ip -n rt route add default via 10.0.255.1` (실습 3 3단계 가.) |
| 4 | 라우팅 | `ip route \| grep 10.0.0.0` | `10.0.0.0/16 via 10.0.255.2 dev igw` | `sudo ip route add 10.0.0.0/16 via 10.0.255.2` (실습 3 3단계 가.) |
| 5 | 라우팅 (NAT) | `sudo iptables -t nat -S \| grep 10.0.0.0` | `-A POSTROUTING -s 10.0.0.0/16 ! -d 10.0.0.0/16 -j MASQUERADE` | `sudo iptables -t nat -A POSTROUTING -s 10.0.0.0/16 ! -d 10.0.0.0/16 -j MASQUERADE` (실습 3 3단계 나.) |
| 6 | 포트 | `sudo iptables -t nat -S \| grep 10.0.1.10` | `-A PREROUTING -d 10.10.1.N/32 -p tcp -m tcp --dport 9080 -j DNAT --to-destination 10.0.1.10:80`<br>`-A OUTPUT -d 10.10.1.N/32 -p tcp -m tcp --dport 9080 -j DNAT --to-destination 10.0.1.10:80`<br>(`10.10.1.N` = 내 VM 주소, `-m tcp`는 iptables가 붙여 보여 주는 것) | 다른 줄을 아래 방법으로 **먼저 지우고**, `VM=$(hostname -I \| cut -d' ' -f1)` 뒤 실습 3 4단계 나.의 두 줄 |
| 7 | 방화벽 | `db iptables -S` | `-P INPUT DROP`<br>`-P FORWARD ACCEPT`<br>`-P OUTPUT ACCEPT`<br>`-A INPUT -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT`<br>`-A INPUT -s 10.0.1.0/24 -p tcp -m tcp --dport 5432 -j ACCEPT`<br>(넣을 때 쓴 `ESTABLISHED,RELATED`가 `RELATED,ESTABLISHED`로 바뀌어 보이는 것은 정상) | 빠진 줄은 실습 4 2단계의 그 줄. 대역이 다른 줄은 아래 방법으로 지움 |
| 8 | 앱 | `curl -s $VM:9080` | `web 10.0.1.10` (실습 3 4단계 나.의 출력과 같음) | 1~7이 모두 같은데 이 줄만 다르면 web 서버가 꺼진 것 → 실습 3 4단계 첫 명령의 `web sh -c …` 줄 |
| 9 | 앱 | `web curl -s -m 3 10.0.2.10:5432` | `db 10.0.2.10` (실습 4 1·2단계의 출력과 같음) | 1~7이 모두 같은데 이 줄만 다르면 db 서버가 꺼진 것 → 실습 3 4단계 첫 명령의 `db sh -c …` 줄 |

- 2~5번은 네 칸 모두 봅니다. 하나가 다르다고 나머지를 건너뛰지 않습니다. 다른 층도 마찬가지입니다
- 8번의 `$VM`이 비어 있으면(새 터미널) `VM=$(hostname -I | cut -d' ' -f1)`을 먼저 칩니다
- 한 칸을 고쳐도 `vpc-check.sh`가 그대로일 수 있습니다. 확인 한 줄에 여러 층의 고장이 겹쳐 있으면 모두 고쳐야 ✔가 됩니다

**틀린 줄 지우기** (6 · 7번) — `-S`가 보여 준 줄에서 맨 앞 `-A`만 `-D`로 바꾸고, 나머지는 화면에 보인 값 그대로 칩니다. 포트 규칙은 `sudo iptables -t nat -D …`, db 방화벽은 `db iptables -D …`입니다. 지우는 줄의 모양은 실습에서 넣은 줄과 같습니다. 예를 들어 실습 3 4단계 나.의 OUTPUT 줄을 지우는 명령은 다음과 같습니다.

```bash
sudo iptables -t nat -D OUTPUT -d $VM -p tcp --dport 9080 -j DNAT --to-destination 10.0.1.10:80
```

`--dport` 뒤 번호, `--to-destination` 뒤 주소:포트, `-s` 뒤 대역은 **내 화면에 보인 값**으로 바꿔 씁니다. 틀린 줄을 남긴 채 맞는 줄을 `-A`로 뒤에 붙이면 위의 틀린 줄이 먼저 맞을 수 있으니 지우고 넣습니다.

- 처음부터 다시: `sudo bash break-vpc.sh <문제 번호>`(같은 고장) · 새 문제: `sudo bash break-vpc.sh`
- `break-vpc.sh`를 열면 고장 후보는 보이지만 **어느 것이 걸렸는지는 점검표로 봐야** 압니다

**이렇게 나오면 성공**: 점검표 1~9번이 모두 "정상이면" 칸과 같고, `bash vpc-check.sh`가 세 줄 모두 ✔에 마지막 줄 `3/3`.

## 과제 3. 결과 정리

점검표 순서대로 결과 정리 표의 칸을 채웁니다. 칸마다 "정상이면" 칸과 **같음/다름**, 다르면 **화면에 보인 줄**과 **고친 줄**을 적습니다. 마지막으로, 과제 1에서 적은 처음 화면의 번호(`000 [28]` · `[7]` 등)가 실제로 점검표 몇 번의 고장이었는지 한 줄로 적습니다.

**이렇게 나오면 성공**: 점검표 1~9번 칸이 모두 채워져 있고, "다름"인 칸마다 화면에 보인 줄과 고친 줄이 들어 있음.
