# 미션 1. 네트워크 장애 해결

**무엇을 하나요**: 사내망에 장애가 났다고 합시다. 실습 3·4에서 만든 VM 안 사내망(web · db · 라우터 · NAT · 9080 포트 포워딩)에 **스크립트가 고장을 섞어 넣습니다.** 층마다(DNS · 라우팅 · 포트 · 방화벽 · 앱) 고장이 하나씩 있고, 모두 실습에서 직접 넣어 본 줄이 빠지거나 틀린 것입니다. **DNS → 라우팅 → 포트 → 방화벽 → 앱 순서대로** 찾아 고쳐서 확인 세 줄을 모두 ✔로 만듭니다. 목표: `bash vpc-check.sh`의 마지막 줄 `3/3`.

**필요한 것**

| 확인할 것 | 내용 |
|---|---|
| VM | 실습 3·4를 해 본 학생 VM. 사내망은 스크립트가 새로 만들어 줍니다(지금 있는 사내망은 지우고 다시 만듦) |
| 스크립트 | 학생 저장소의 `lab/network/break-vpc.sh`(장애를 넣은 사내망 만들기) · `vpc-check.sh`(세 가지 확인, 원인은 알려 주지 않음) |
| 명령 | 새 명령 없음 — 실습 1~5에서 쓴 `curl` · `dig` · `ip route` · `iptables -S` · `ip netns pids` |
| 끝나면 | `sudo bash ~/ktcloud-cloud-native-lab/lab/network/vpc-down.sh`(클러스터는 그대로) |

> **바로 가기** · [과제 1. 고장 만들고 증상 보기](#과제-1-고장-만들고-증상-보기) · [과제 2. 층마다 찾아 고치기](#과제-2-층마다-찾아-고치기) · [과제 3. 결과 정리](#과제-3-결과-정리) · [결과 정리 표](#결과-정리-표)

## 과제 1. 고장 만들고 증상 보기

장애를 넣은 사내망을 만들고, 확인 세 줄의 curl 번호를 보고 **어느 층부터 볼지** 정합니다. 아직 고치지 않습니다.

```bash
cd ~/ktcloud-cloud-native-lab && git pull && cd lab/network
sudo bash break-vpc.sh
alias web="sudo ip netns exec web" db="sudo ip netns exec db" rt="sudo ip netns exec rt"
bash vpc-check.sh
```

**처음 화면 예** (사람마다 고장이 달라 ✘ 뒤 번호가 다를 수 있음)

```
고장 난 VPC 준비 완료 (문제 번호 2 — 같은 문제를 다시 풀려면 sudo bash break-vpc.sh 2)
층마다(DNS · 라우팅 · 포트 · 방화벽 · 앱) 고장이 하나씩 있습니다. 확인: bash vpc-check.sh
✘ ① db → https://example.com   000 [28]
✘ ② web → db 5432             [7]
✘ ③ VM → 10.10.1.23:9080 (web)   [7]
0/3
```

| 확인 | 뜻 | 정상이면 |
|---|---|---|
| ① | DB 서브넷(내부망)의 db가 이름으로 인터넷(HTTPS)에 나감 | `200` |
| ② | 웹 서브넷의 web이 db의 5432에 닿음 | `db 10.0.2.10` |
| ③ | 밖(VM)에서 포트 포워딩 9080으로 web에 들어옴 | `web 10.0.1.10` |

- 첫 줄의 **문제 번호**를 결과 정리 표에 적습니다. 같은 번호면 같은 고장이라 처음부터 다시 할 수 있습니다
- 확인 줄마다 curl 번호(`[6]` · `[28]` · `[7]`)가 무슨 뜻이었는지 실습 1의 표를 떠올려, 어느 층이 의심되는지 적습니다

<details><summary>힌트 — curl 번호</summary>

`[6]`은 이름을 주소로 못 바꿈, `[28]`은 정해진 시간 안에 답이 없음, `[7]`은 연결 거절(그 포트에 아무도 없음)입니다(실습 1). `000`은 HTTP 응답을 하나도 못 받았다는 뜻입니다.
</details>

**이렇게 나오면 성공**: 마지막 줄이 `0/3`(또는 `1/3`처럼 일부만 ✘)이고, 확인 줄마다 의심되는 층을 하나씩 적었음.

## 과제 2. 층마다 찾아 고치기

과제 1에서 의심한 층이 있어도 **DNS 층부터 차례로** 봅니다. 층마다 본 명령 · 본 화면 · 고친 줄을 적어 두면 과제 3이 쉬워집니다.

**찾는 순서** — 위에서 아래로. 한 층을 고칠 때마다 `bash vpc-check.sh`

| 층 | 묻는 것 | 보는 명령 (배운 곳) |
|---|---|---|
| 1 DNS | 이름이 주소로 바뀌나 | `db cat /etc/resolv.conf` · `db dig +short +time=2 +tries=1 example.com` · 같은 것을 `@8.8.8.8`로 (실습 1, 실습 3 5단계) |
| 2 라우팅 | 그 주소로 가고 돌아오는 경로가 있나 | `db ip route` · `rt ip route` · `ip route \| grep 10.0.0.0` · `sudo iptables -t nat -S POSTROUTING` · `db curl -s -m 4 -o /dev/null -w "%{http_code}\n" http://1.1.1.1` (실습 3 3~5단계) |
| 3 포트 | 입구 규칙이 맞는 곳(포트)을 가리키나 | `sudo iptables -t nat -S \| grep 10.0.1.10` (실습 3 6단계) |
| 4 방화벽 | 규칙이 요청이나 답을 버리나 | `db iptables -S` · `rt iptables -S FORWARD` (실습 4) |
| 5 앱 | 서버 프로그램이 떠 있나 | `sudo ip netns pids web` · `sudo ip netns pids db` — 빈 출력이면 꺼짐 (실습 5 4단계) |

- 고친 줄은 **결과 정리 표**에 층 · 본 화면 · 고친 줄로 적습니다
- 처음부터 다시: `sudo bash break-vpc.sh <문제 번호>`(같은 고장) · 새 문제: `sudo bash break-vpc.sh`
- `break-vpc.sh`를 열면 고장 후보는 보이지만 **어느 것이 걸렸는지는 사내망을 봐야** 압니다

<details><summary>힌트 1 — 어디서부터</summary>

①이 이름으로 안 되면 먼저 **주소로**(`http://1.1.1.1`) 해 봅니다. 주소로도 안 되면 이름보다 길이 먼저입니다. `dig`를 `@8.8.8.8`로 직접 물어도 안 되면 역시 길 문제입니다(실습 3 5단계 "DNS 서버가 틀리면").
</details>

<details><summary>힌트 2 — 길과 포트</summary>

실습 3에서 넣은 길은 네 가지였습니다: web·db의 기본 경로, 라우터의 기본 경로(`10.0.255.1`), VM의 `10.0.0.0/16 via 10.0.255.2`, NAT(MASQUERADE) 한 줄. 9080 입구 규칙은 두 줄(PREROUTING · OUTPUT)이고 목적지가 `10.0.1.10:80`이어야 합니다. 틀린 줄은 `-S`로 본 줄의 `-A`를 `-D`로 바꿔 `sudo iptables -t nat -D …`로 지우고, 맞는 줄을 다시 넣습니다.
</details>

<details><summary>힌트 3 — 방화벽과 앱</summary>

서버 방화벽(db의 INPUT)은 실습 4 2단계의 세 줄과 비교합니다: 답 허용(ESTABLISHED) · web 서브넷 `10.0.1.0/24`의 5432 · 나머지 DROP. 라우터 ACL(라우터의 FORWARD)에 `-d 10.0.2.0/24 -j DROP`이 있으면 db로 돌아오는 답도 막힙니다(실습 4 3·4단계 — 답 규칙을 넣거나 `rt iptables -F`). 서버를 다시 켜는 줄은 실습 3 6단계(web 80, db 5432)에 있습니다.
</details>

**이렇게 나오면 성공**: `bash vpc-check.sh`가 세 줄 모두 ✔이고 마지막 줄 `3/3`.

## 과제 3. 결과 정리

고친 과정을 **층마다 한 줄씩** 결과 정리 표에 적습니다. 각 줄은 "본 명령 → 본 화면 → 고친 줄 → 고친 뒤 `vpc-check.sh`" 순서입니다. 마지막으로, 처음 화면의 curl 번호(`[28]` · `[7]`)가 실제로 어느 층의 고장이었는지 한 줄로 적습니다.

**이렇게 나오면 성공**: DNS · 라우팅 · 포트 · 방화벽 · 앱 다섯 줄이 모두 채워져 있고, 각 줄에 "어떤 화면을 보고 그 층이라고 판단했는지"가 들어 있음.
