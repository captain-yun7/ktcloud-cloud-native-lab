# 자주 쓴 명령과 오류

## 자주 쓴 명령

| 명령 | 하는 일 | 실습 |
|---|---|---|
| `kubectl -n other exec t -- nc -z -w 3 서비스.네임스페이스 포트 && echo 열림 \|\| echo 막힘` | 그 서비스 포트에 연결되는지 시험 — `열림`/`막힘` | 1, 7 |
| `kubectl -n todo exec deploy/api -- ps` | 컨테이너 안 프로그램과 실행 사용자 | 1, 4 |
| `kubectl auth can-i 동사 리소스 -n 네임스페이스 --as=계정` | 그 계정의 권한 묻기 | 1, 6 |
| `trivy image --severity HIGH,CRITICAL --table-mode detailed 이미지` | 이미지 취약점 스캔 | 2, 3 |
| `trivy config 폴더` | Dockerfile 설정 점검 | 3 |
| `kind load docker-image 이미지 --name lab` | 이미지를 클러스터에 넣기 | 3 |
| `kubectl -n todo get events --field-selector reason=Failed` (또는 `FailedCreate`) | 파드가 안 뜬 이유 | 4, 8 |
| `kubectl -n todo get secret 이름 -o jsonpath='{.data.키}' \| base64 -d` | Secret 값 되돌리기 | 5 |
| `kubectl label namespace 이름 pod-security.kubernetes.io/enforce=restricted --dry-run=server` | restricted 라벨을 붙이면 어느 파드가 걸리는지 미리 보기(Warning 줄) | 8 |
| `kubectl get validatingpolicy` | Kyverno 정책 확인 | 9 |
| `trivy image --format cyclonedx -o 파일 이미지` / `trivy sbom 파일` | SBOM 만들기 / 스캔 | 10 |
| `cosign sign` / `cosign verify` | 서명 / 검증 | 10 |

## 자주 만나는 오류 한눈에

| 화면 | 원인 | 해결 | 실습 |
|---|---|---|---|
| api·web이 `ErrImagePull` | 클러스터 안에 todo 이미지가 없음 | 시작하기 전에 4 | 1 |
| `wget: server returned error: HTTP/1.1 500` | db가 새로 만들어져 테이블이 없음 | `kubectl -n todo rollout restart deployment/api` | 1~ |
| `grep Total`이 아무것도 안 보여 줌 | 취약점 0건이면 `Total` 줄이 없음 | `grep` 없이 표가 있는지 봄 | 2, 3 |
| `CreateContainerConfigError`, `image will run as root` | `runAsNonRoot`인데 이미지가 root | 이미지에 `USER 1000`(실습 3) 또는 `runAsUser` | 4 |
| `touch: … Read-only file system` | `readOnlyRootFilesystem` (의도한 것) | 쓰기가 필요한 폴더만 emptyDir | 4 |
| `The Pod "…" is invalid: … pod updates may not change fields` | 만든 파드를 고쳐 apply | `kubectl delete pod …` 후 다시 apply | 5 |
| 토큰 접속인데 Secret이 조회됨 | `--kubeconfig=/dev/null`을 빠뜨려 관리자로 접속 | `--kubeconfig=/dev/null` 붙이기 | 6 |
| 정책을 걸었는데 아직 연결됨 | 정책은 **새 연결**부터 적용, 또는 apply 안 됨 | `kubectl -n todo get networkpolicy`, 다시 시험 | 7 |
| `Deployment`는 있는데 파드가 0개 | PSA가 파드를 거부(`FailedCreate`) | `get events`의 `FailedCreate` 이유를 보고 `runAsNonRoot`·`capabilities.drop` 등 실습 4의 설정을 넣음 | 8, 미션 |
| `failed calling webhook "validate-policy.kyverno.svc" … connection refused` | Kyverno 준비 중 | 몇 초 뒤 같은 apply 다시 | 9 |
| 서명이 레지스트리 주소 없는 이름으로 실패 | `docker inspect`의 RepoDigests 사용 | `docker buildx imagetools inspect` | 10 |
| `port is already allocated` | 앞에서 띄운 컨테이너가 남음 | `docker rm -f 이름` 후 다시 | 10 |
