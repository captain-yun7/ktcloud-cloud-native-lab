# 시작하기 전에

실습 1을 시작하기 전에 한 번 읽어 주세요. 접속·붙여넣기·PORTS 탭은 Kubernetes 과목과 같습니다. 자세한 설명은 [Kubernetes 실습 문서의 시작하기 전에](../../02-kubernetes/실습/00-시작하기-전에.md#시작하기-전에)에 있습니다. 아래 3·4번(보안 도구 설치, todo 이미지 준비)은 **실습 1 전에 꼭 한 번** 합니다.

## 1. 접속과 명령 치는 곳

- 접속 명령: `ssh ktc-sNN` — `NN`은 본인 번호 두 자리. 자세한 절차는 [접속 안내](../../00-접속-안내.md)
- **이 문서의 명령은 전부 서버 VM의 터미널에 칩니다.** 터미널 맨 앞이 `lab@sNN:~$`이면 서버 VM입니다
- 회색 코드 블록 오른쪽 위의 복사 버튼 → 서버 터미널에 붙여 넣기. 마지막 줄이 실행되지 않고 남아 있으면 **Enter**를 한 번 더 누릅니다
- 코드 블록의 `#` 뒤는 설명(주석)이라 같이 붙여 넣어도 실행되지 않습니다. 결과만 적힌 블록(화면 예)은 붙여 넣지 않고 내 화면과 비교만 합니다
- YAML 파일은 `nano 파일이름`으로 열어 붙여 넣고 **Ctrl+O → Enter → Ctrl+X**로 저장합니다. 들여쓰기는 스페이스 2칸, 탭 금지(Kubernetes 시작하기 전에 7)

## 2. 클러스터가 떠 있는지 확인

실습을 시작할 때마다 먼저 확인합니다.

```bash
kubectl get nodes
```

**이렇게 나오면 성공**: `lab-control-plane   Ready   control-plane …`

**이렇게 나오면?**
| 화면 | 원인 | 해결 |
|---|---|---|
| `The connection to the server … was refused` | 클러스터가 꺼짐(VM을 다시 켠 뒤 등) | [Kubernetes 시작하기 전에 6](../../02-kubernetes/실습/00-시작하기-전에.md#6-클러스터가-떠-있는지-확인-실습-2부터-매번) |
| `kubectl: command not found` | 새 터미널에 설정이 안 읽힘 | `source ~/.bashrc` |

## 3. 보안 도구 설치 — make tools

실습 저장소를 최신으로 받고, 보안 도구 trivy(점검)·cosign(서명)을 설치합니다.

```bash
cd ~/ktcloud-cloud-native-lab && git pull
cd lab && make tools        # trivy·cosign이 추가되었습니다
source ~/.bashrc
trivy --version | head -1
cosign version | grep GitVersion
```

**이 명령은**: `git pull` = 실습 저장소를 최신으로 받음(이 과목의 `todo.yaml`도 같이 받음). `make tools` = 실습에 쓰는 도구를 설치(Kubernetes 실습 1과 같은 명령, 보안 도구가 더해짐). `source ~/.bashrc` = 지금 터미널에 새 설정을 읽힘.

**이렇게 나오면 성공**

```
Version: 0.74.0
GitVersion:    v3.1.3
```

**이렇게 나오면?**
| 화면 | 원인 | 해결 |
|---|---|---|
| `trivy: command not found` | 설정을 다시 안 읽음 | `source ~/.bashrc` 또는 터미널을 새로 열기 |
| `make: *** No rule to make target 'tools'.` | `lab` 폴더 밖에서 실행 | `cd ~/ktcloud-cloud-native-lab/lab` 후 다시 |

## 4. todo 이미지 준비

실습 앱 todo의 이미지 `todo-api:v1`·`todo-web:v1`은 Kubernetes 실습 7에서 만들어 클러스터에 넣었습니다. 클러스터를 다시 만들었으면(`make reset` 등) 클러스터 안에는 없으니, 한 번 더 만들어 넣습니다. 이미 있으면 금방 끝나므로 **누구나 그대로 실행**합니다.

```bash
cd ~/ktcloud-cloud-native-lab/lab/docker/todo
docker build -t todo-api:v1 api
docker build -t todo-web:v1 web
kind load docker-image todo-api:v1 todo-web:v1 --name lab
```

**이 명령은**: Kubernetes 실습 7의 1단계와 같은 명령입니다. `docker build` = 이미지 만들기(바뀐 것이 없으면 캐시로 몇 초), `kind load docker-image` = 이미지를 클러스터 노드에 넣기.

**이렇게 나오면 성공**: 빌드 두 번이 오류 없이 끝나고, 마지막에 이미지마다 둘 중 하나

```
Image: "todo-api:v1" with ID "sha256:…" not yet present on node "lab-control-plane", loading...
Image: "todo-api:v1" with ID "sha256:…" found to be already present on all nodes.
```

**이렇게 나오면?**
| 화면 | 원인 | 해결 |
|---|---|---|
| `cd: … lab/docker/todo: No such file or directory` | 저장소를 최신으로 안 받음 | 3번의 `git pull` |
| `ERROR: no nodes found for cluster "kind"` | `--name lab`을 빠뜨림 | `--name lab`을 붙여 다시 |

## 5. 출력이 문서와 조금 달라도 되는 것

| 달라도 되는 것 | 예 |
|---|---|
| 취약점 개수 | 취약점 DB가 매일 바뀜. "어느 쪽이 더 적은가"만 같으면 됨 |
| trivy의 `INFO`·`WARN` 줄, 맨 끝 `Notices: Version 0.75.0 of Trivy is now available` | 도구가 남기는 안내. 무시해도 됨 |
| 파드 이름 뒤의 무작위 글자, IP, `AGE` | `api-7bcdc699f-gmv69`의 `7bcdc699f-gmv69` |
| 다이제스트(`sha256:…`) | 이미지를 만들 때마다 다름 |

**같아야 하는 것**은 "이렇게 나오면 성공"에서 짚은 값입니다(예: `uid=0(root)`, `열림`/`막힘`, `yes`/`no`, `Forbidden`).

## 6. 막히면 — 질문하는 법

1. 에러의 **첫 줄**을 읽고, 그 단계의 **이렇게 나오면?** 표와 [자주 쓴 명령과 오류](./99-자주-쓴-명령과-오류.md#자주-만나는-오류-한눈에)에서 같은 문구를 찾아봅니다
2. 파드가 이상하면 `kubectl -n todo get pods`의 `STATUS` → `kubectl -n todo describe pod <이름>`의 맨 아래 **Events** → `kubectl -n todo logs <이름>` 순서로 봅니다(Kubernetes 08장)
3. 그래도 모르겠으면 Discord에 질문합니다. 에러는 **사진이 아니라 글자로** 붙이고, 아래 네 가지를 같이 적습니다. 비밀번호·토큰·키는 지우고 올립니다

```
[실습 4 - 2단계] (몇 번 실습, 몇 단계)
한 일: kubectl apply -f api-secure.yaml
기대: 새 api 파드가 CreateContainerConfigError
실제: 새 api 파드가 Running
해 본 것: kubectl -n todo get pods (그대로 붙여넣기)
```

## 이 문서에 나오는 말

| 말 | 쉬운 뜻 |
|---|---|
| uid, root | 리눅스 사용자 번호. **0번이 root**(관리자, 무엇이든 할 수 있음) |
| 비루트 | root가 아닌 사용자(예: uid 1000)로 프로그램을 돌리는 것 |
| 네임스페이스 | 클러스터 안을 나눈 칸. 이 과목은 `todo`, `other`, `psa`, `shop`을 씀 |
| 서비스 계정, 토큰 | 사람이 아니라 **파드(프로그램)가 쓰는 계정**, 그 계정임을 증명하는 긴 문자열 |
| base64 | 글자를 다른 글자로 바꿔 적는 방법. **암호화가 아님** — 누구나 되돌릴 수 있음 |
| 취약점, CVE | 프로그램에서 발견된 보안 결함, 그 결함에 붙는 세계 공통 번호(`CVE-2026-…`) |
| 심각도 | 취약점·설정 문제에 붙는 등급. CRITICAL > HIGH > MEDIUM > LOW. 예) `todo-api:v1`은 HIGH 11개(실습 2) |
| 바탕 이미지 | Dockerfile의 `FROM`에 적은 이미지. 그 안의 파일이 모두 내 이미지에 들어감 |
| 설정 점검 (misconfig) | 코드 결함이 아니라 **설정이 위험한 것**을 찾는 점검(예: root로 실행) |
| SecurityContext | 파드 YAML에 적는 "누구로, 어떤 제한으로 돌릴지" 설정 |
| RBAC | 누가(계정) 무엇을(리소스) 어떻게(조회·삭제…) 할 수 있는지 정하는 권한 규칙 |
| NetworkPolicy | 어느 파드가 어느 파드에 연결할 수 있는지 정하는 규칙 |
| PSA (Pod Security Admission) | 네임스페이스에 라벨 하나를 붙이면, `runAsNonRoot` 같은 설정이 빠진 파드를 만들 때 `Forbidden`으로 거부하는 기능(실습 8) |
| Kyverno | 우리가 만든 규칙(예: latest 태그 금지)을 어기는 파드를 만들 때 거부하는 도구(실습 9) |
| SBOM | 이미지 안에 들어 있는 **구성요소 목록** 파일 |
| 다이제스트 | 이미지 내용으로 계산한 고유 값(`sha256:…`). 내용이 1바이트만 바뀌어도 달라짐 |
| 서명 | 비밀키로 다이제스트에 붙이는 표시. 공개키로 "그 뒤로 안 바뀌었음"을 확인 |
