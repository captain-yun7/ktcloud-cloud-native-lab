# 자주 쓴 명령과 오류

## 자주 쓴 명령

| 명령 | 하는 일 |
|---|---|
| `make envoy-gateway` | Envoy Gateway 설치 (`lab` 폴더에서) |
| `kubectl get gatewayclass` | 입구를 만들 프로그램 목록 (`eg`) |
| `kubectl -n gateway get gateway` | 입구 목록, `PROGRAMMED` |
| `kubectl get httproute -A` | 모든 네임스페이스의 경로 규칙 |
| `kubectl -n todo get securitypolicy,backendtrafficpolicy` | 붙인 정책 목록 |
| `kubectl -n todo get securitypolicy <이름> -o jsonpath='{.status.ancestors[0].conditions[0].reason}'` | 정책이 받아들여졌나(`Accepted`) |
| `curl -s -o /dev/null -w "%{http_code}\n" <주소>` | 상태 코드만 보기 |
| `curl -s -H "이름: 값" <주소>` | 헤더를 넣어 부르기 |
| `curl -s -D - <주소>` | 응답 헤더도 보기 |
| `curl -s -H "x-api-key: key-aaa" todo.localhost:8080/api/me` | 앱(v2)이 받은 헤더 보기 |
| `kubectl -n envoy-gateway-system logs -l gateway.envoyproxy.io/owning-gateway-name=front -c envoy --tail=1` | 입구가 남긴 마지막 요청 기록 |
| `for i in $(seq 1 7); do curl -s -o /dev/null -w "%{http_code} " …; done; echo` | 여러 번 부르고 코드를 한 줄로 |
| `kubectl -n todo get httproute <이름> -o yaml \| sed -n '/^status:/,$p'` | 경로 규칙의 처리 결과(`Accepted`·`ResolvedRefs`, 이유 `message`) |
| `kubectl -n gateway get gateway front -o jsonpath='{range .status.listeners[*]}{.name} {.attachedRoutes}{"\n"}{end}'` | 입구의 창구(리스너)마다 붙은 경로 수 |
| `curl -s -w " %{http_code} %{time_total}\n" <주소>` | 상태 코드와 걸린 초 |
| `seq 1 10 \| xargs -P 10 -I{} curl -s -o /dev/null -w "%{http_code}\n" <주소>` | 10개를 동시에 |
| `curl -s -D - -X OPTIONS -H "Origin: …" -H "Access-Control-Request-Method: GET" <주소>` | 브라우저의 CORS 미리 묻기 흉내 |
| `while true; do kubectl -n envoy-gateway-system port-forward $SVC 8443:443; sleep 1; done > /dev/null 2>&1 &` | VM 8443 → 입구 443(실습 8 3단계, `SVC=` 줄 먼저) |
| `curl -s --cacert ~/apigw/tls/ca.crt https://todo.localhost:8443/…` | 수업용 CA를 믿고 HTTPS로 부르기 |

## 자주 만나는 오류 한눈에

| 화면 | 원인 | 해결 |
|---|---|---|
| `curl: (56) Recv failure: Connection reset by peer` (8080) | 8080 뒤에 Envoy가 없음 — 설치 전, Gateway 전, 매핑 없음 | 실습 1의 1·3·4단계 |
| `404` (본문 없음) | 이름·경로가 어느 HTTPRoute에도 안 맞음 | `kubectl get httproute -A`의 `HOSTNAMES`, `path`, HTTPRoute의 `Accepted`(실습 1 7단계) |
| `500` (본문 없음) | HTTPRoute가 보낼 Service를 못 찾음(`ResolvedRefs=False`) | `-o yaml`의 status `message`(실습 1 7단계) |
| `/v1/…`이 `404`, web이 받음 | 버전 경로 규칙이 없음, 또는 `URLRewrite` 빠짐 | 실습 2의 6단계 |
| 정책 상태 `Conflicted` | 같은 HTTPRoute에 같은 종류 정책이 이미 있음 | 한 파일에 합침(실습 6 3단계, 실습 7 2단계) |
| `404` `Cannot GET /api/…` | 앱까지 갔지만 앱에 그 주소가 없음(v1에는 `/api/me`가 없음) | 실습 2의 5단계(v2로 다 옮기기) |
| `401` `Client authentication failed.` | API 키가 없거나 틀림 | 실습 3, `x-api-key: key-aaa` |
| `401` `Jwt is missing` · `Jwt verification fails` | 토큰이 없음 · 서명이 안 맞음(새 터미널이라 `$TOK`가 빔) | 실습 4의 1단계 `TOK=` 줄 |
| `429` `local_rate_limited` | 1분 한도를 넘음 | 응답의 `x-ratelimit-reset`초만큼 기다림 |
| `503` `upstream connect error … connection termination` | 앱 파드에 못 붙음 — Istio mTLS STRICT, 또는 앱 파드 없음 | `kubectl get peerauthentication -A`, `kubectl -n todo get pods`. 질문 |
| `504` `upstream request timeout` | 앱이 `timeouts.request`보다 늦음(없으면 15초) | 실습 6의 2단계, 미션 도전 B |
| `503` `… reset reason: overflow` | 동시 요청 한도를 넘음 | 실습 6의 5단계 — 정상 |
| CORS 미리 묻기(`OPTIONS`)가 `401` | 키 정책만 있고 `cors`가 없음 | 실습 7의 3단계 |
| `curl: (60) SSL certificate problem: unable to get local issuer certificate` | 수업용 CA를 curl이 모름 | `--cacert ~/apigw/tls/ca.crt` |
| `curl: (35) … SSL_ERROR_SYSCALL` | 그 이름의 HTTPS 창구(리스너)가 없음 | 리스너 `hostname`. 이 뒤 8443 잇기가 한 번 끊김 — 3초 뒤 다시 |
| `curl: (7) Failed to connect to … port 8443` | 8443 잇기(port-forward)가 없음 | 실습 8 3단계 나의 첫 세 줄 |
| `http`로 불렀는데 `301`이 아니라 `200` | 경로가 아직 `http` 창구에도 붙음(`RouteRulesOverlap=True`) | 실습 8 5단계 나(`sectionName: https`) |
| 앞 실습 명령이 모두 `301` | 실습 8 5단계 뒤 — 정상 | `https://todo.localhost:8443/…` + `--cacert`, 또는 `curl -L` |
| 정책을 apply했는데 그대로 | 반영까지 몇 초, 또는 `targetRefs` 이름 오타 | 10초 뒤 다시, 정책 reason이 `Accepted`인지 |
| 브라우저 todo 화면에 `api 연결 실패: HTTP 401` | 실습 3 뒤 — 화면도 키 없는 손님 | 정상(실습 3의 4단계) |
