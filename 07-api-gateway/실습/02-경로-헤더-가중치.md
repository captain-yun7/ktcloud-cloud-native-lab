# 실습 2. 경로 · 헤더 · 가중치 · API 변환

**무엇을 하나요**: 같은 `todo.localhost:8080` 안에서 **`/api`로 시작하는 요청은 api로 바로**, 나머지는 web으로 나눕니다. 그다음 todo-api **v2**를 만들어 v1 옆에 띄우고, 헤더 `x-version: v2`면 v2로, 나머지는 v1 **80** : v2 **20**으로 나눠 보냅니다(카나리). /api를 모두 v2로 옮기면서 요청 헤더를 하나 더하고 응답 헤더를 하나 지웁니다. 마지막에 바깥 주소 **`/v1/…`·`/v2/…`**(API 버전)를 입구에서 앱이 아는 `/api/…`로 **바꿔** v1·v2에 보냅니다(API 변환). (교안 03장)

**필요한 것**: 실습 1의 입구 `front`, HTTPRoute `todo`. 모니터링 실습 4에서 만든 `~/mon/api-metrics`(지표가 달린 todo-api 소스).

## 1단계. 나누기 전 — /api도 web을 거침

```bash
cd ~/apigw
curl -s -D - -o /dev/null todo.localhost:8080/api/todos | grep -i "decorator\|powered"
kubectl -n todo logs deploy/web -c nginx --since=10s | grep "curl/8.5"
```

**이 명령은**: 첫째 = `/api/todos`를 부르고 응답 헤더 중 두 줄만 봄. 둘째 = web(nginx)의 최근 10초 로그에서 VM의 curl(버전 8.5)이 보낸 요청만 봄(1초마다 부르는 `load` 파드는 curl 8.16이라 안 걸림).

**이렇게 나오면 성공**

```
x-powered-by: Express
x-envoy-decorator-operation: web.todo.svc.cluster.local:80/*
127.0.0.6 - - [17/Oct/2026:15:21:00 +0000] "GET /api/todos HTTP/1.1" 200 40 "-" "curl/8.5.0" "172.18.0.4"
```

- `web.todo…` = 요청이 web 파드 앞(Istio 사이드카)을 지나 왔다는 표시입니다. web 로그에도 내 요청이 있습니다. 실습 1의 HTTPRoute가 **모든 경로**를 web으로 보내고, web(nginx)이 `/api/`를 안에서 api로 넘기기 때문입니다
- 이대로면 API에만 키 검사를 붙일 자리가 없습니다. 화면과 API가 한 규칙에 묶여 있습니다

## 2단계. /api는 api로 — 경로 나누기

```bash
nano todo-api-route.yaml
```

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: todo-api
  namespace: todo
spec:
  parentRefs:
  - name: front
    namespace: gateway
  hostnames: ["todo.localhost"]
  rules:
  - matches:
    - path:
        type: PathPrefix
        value: /api
    backendRefs:
    - name: api
      port: 3000
```

| 줄 | 뜻 |
|---|---|
| `name: todo-api` | 실습 1의 `todo`와 **다른** HTTPRoute. 같은 이름(`todo.localhost`)에 둘이 붙음 |
| `matches: - path: type: PathPrefix, value: /api` | 경로가 `/api`로 시작하면(`/api`, `/api/todos` …) |
| `backendRefs: - name: api, port: 3000` | web을 거치지 않고 Service `api`로 바로 |

```bash
kubectl apply -f todo-api-route.yaml
kubectl -n todo get httproute
curl -s -D - -o /dev/null todo.localhost:8080/api/todos | grep -i "decorator"
curl -s -D - -o /dev/null todo.localhost:8080/ | grep -i "decorator"
kubectl -n todo logs deploy/web -c nginx --since=10s | grep "curl/8.5"
```

**이렇게 나오면 성공**: `/api/todos`는 **api**, `/`는 그대로 **web**. web 로그에는 `GET /`만 남음

```
httproute.gateway.networking.k8s.io/todo-api created
NAME       HOSTNAMES            AGE
todo       ["todo.localhost"]   2m28s
todo-api   ["todo.localhost"]   3s
x-envoy-decorator-operation: api.todo.svc.cluster.local:3000/*
x-envoy-decorator-operation: web.todo.svc.cluster.local:80/*
127.0.0.6 - - [17/Oct/2026:14:53:21 +0000] "GET / HTTP/1.1" 200 489 "-" "curl/8.5.0" "172.18.0.3"
```

- HTTPRoute가 둘이지만 둘 다 `todo.localhost`입니다. Envoy는 둘을 합쳐 **더 구체적인 규칙**(`/api`)을 먼저 봅니다. 조건 없는 `todo`(=`/`)는 나머지를 받습니다

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `/api/todos`가 여전히 `web.todo…` | apply 직후, 또는 `value: /api` 오타 | 5초 뒤 다시, `cat todo-api-route.yaml` |
| `/api/todos`가 `503` | `port: 3000`을 80으로 씀 | Service api는 3000번(`kubectl -n todo get svc api`) |
| `- path:` 줄이 `matches`와 같은 칸 | 들여쓰기 | 위 파일과 칸 단위로 비교 |

</details>

## 3단계. todo-api v2 만들기

모니터링 실습 4에서 지표를 단 todo-api 소스를 복사해, 두 군데를 고친 **v2**를 만듭니다.

```bash
cp -r ~/mon/api-metrics ~/apigw/api-v2
cd ~/apigw/api-v2
sed -i "s/res.json({ ok: true })/res.json({ ok: true, version: 2 })/" app.js
nano app.js
```

`app.get('/api/health', …)` 줄을 찾아 **바로 아래**에 다음을 붙여 넣고 저장합니다(**Ctrl+O → Enter → Ctrl+X**).

```js
// --- API Gateway 실습: 게이트웨이가 붙여 준 헤더를 그대로 보여 줌 ---
app.get('/api/me', (req, res) => res.json({
  version: 2,
  gateway: req.get('x-gateway') || null,
  client: req.get('x-client-id') || null,
  user: req.get('x-user-name') || null,
  apiKey: req.get('x-api-key') || null,
}));
```

| 부분 | 뜻 |
|---|---|
| `sed -i "s/A/B/" app.js` | `/api/health`의 응답에 `version: 2`를 더함 — v1과 구별 |
| `app.get('/api/me', …)` | 새 주소. 앱이 **받은 헤더** 넷을 그대로 돌려줌. 없으면 `null` |

```bash
grep -n "api/health\|api/me" app.js
docker build -t todo-api:v2 .
kind load docker-image todo-api:v2 --name lab
cd ~/apigw
nano api-v2.yaml
```

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-v2
  namespace: todo
spec:
  replicas: 1
  selector:
    matchLabels:
      app: api-v2
  template:
    metadata:
      labels:
        app: api-v2
    spec:
      containers:
      - name: api
        image: todo-api:v2
        envFrom:
        - configMapRef:
            name: todo-config
        env:
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: todo-secret
              key: DB_PASSWORD
        ports:
        - containerPort: 3000
---
apiVersion: v1
kind: Service
metadata:
  name: api-v2
  namespace: todo
spec:
  selector:
    app: api-v2
  ports:
  - name: http
    port: 3000
```

**이 파일은**: v1(`todo.yaml`의 api)과 같은 설정(같은 DB)으로 이미지만 `todo-api:v2`. 라벨이 `app: api-v2`라서 기존 Service `api`는 v1만, 새 Service `api-v2`는 v2만 고릅니다.

```bash
kubectl apply -f api-v2.yaml
kubectl -n todo rollout status deploy/api-v2
kubectl -n todo get pods -L app
```

## 4단계. 80:20과 헤더로 v2 고르기

**가. 나누기 전** — v2를 띄웠지만 입구 규칙은 아직 api(v1)만 가리킵니다.

```bash
for i in $(seq 1 100); do curl -s todo.localhost:8080/api/health; echo; done | sort | uniq -c
```

**이렇게 나오면 성공**: `100 {"ok":true}` — v2는 떠 있지만 아무 요청도 못 받음.

**나. 규칙 두 개로** — `todo-api-route.yaml`을 아래처럼 고칩니다.

```bash
nano todo-api-route.yaml
```

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: todo-api
  namespace: todo
spec:
  parentRefs:
  - name: front
    namespace: gateway
  hostnames: ["todo.localhost"]
  rules:
  - matches:
    - path:
        type: PathPrefix
        value: /api
      headers:
      - name: x-version
        value: v2
    backendRefs:
    - name: api-v2
      port: 3000
  - matches:
    - path:
        type: PathPrefix
        value: /api
    backendRefs:
    - name: api
      port: 3000
      weight: 80
    - name: api-v2
      port: 3000
      weight: 20
```

| 규칙 | 뜻 |
|---|---|
| 첫째 `matches`에 `headers: x-version: v2` | `/api`이면서 헤더 `x-version: v2`가 있으면 v2로만 — 먼저 써 볼 사람(시험자) |
| 둘째 `backendRefs` 둘에 `weight` 80 · 20 | 나머지 `/api`는 v1 80 : v2 20으로 나눔 |

```bash
kubectl apply -f todo-api-route.yaml
for i in $(seq 1 100); do curl -s todo.localhost:8080/api/health; echo; done | sort | uniq -c
for i in 1 2 3 4 5; do curl -s -H "x-version: v2" todo.localhost:8080/api/health; echo; done | sort | uniq -c
curl -s -H "x-version: v2" todo.localhost:8080/api/me; echo
```

**이렇게 나오면 성공**: 헤더 없이 100번 중 v2가 20번 안팎, 헤더를 넣으면 5번 모두 v2, `/api/me`는 헤더 넷이 모두 `null`(아직 아무도 안 붙임)

```
     80 {"ok":true}
     20 {"ok":true,"version":2}
      5 {"ok":true,"version":2}
{"version":2,"gateway":null,"client":null,"user":null,"apiKey":null}
```

| | 가. 규칙이 v1만 | 나. 80:20 + 헤더 |
|---|---|---|
| 헤더 없이 100번 | v1 100 | v2 20번 안팎 |
| v2에 버그가 있으면 | (v2를 아무도 안 씀) | 약 20%와 시험자만 겪음 |
| 먼저 써 볼 사람 | 고를 수 없음 | `x-version: v2` 헤더 |
| 되돌리기 | — | v2 `weight`를 0으로 — 파드는 그대로 |

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| 100번 모두 `{"ok":true}` | apply 직후, 또는 `weight` 줄이 빠짐 | 5초 뒤 다시, `cat todo-api-route.yaml` |
| 헤더를 넣어도 v1이 섞임 | `headers:`가 `path:`와 같은 칸이 아님, 또는 값 오타(`V2`) | 위 파일과 칸 비교. 값은 대소문자 구분 |
| `/api/me`가 `Cannot GET /api/me` | 헤더 없이 불러 v1로 감 | `-H "x-version: v2"`를 넣음 |

</details>

## 5단계. v2로 다 옮기고 헤더 더하기·지우기

v2에 문제가 없다고 보고 `/api`를 모두 v2로 옮깁니다. 같이 두 가지를 손봅니다. 응답에 붙어 나가는 `x-powered-by: Express`(앱 종류를 바깥에 알려 줌)를 지우고, 앱에 가는 요청에는 `x-gateway: front`(입구를 거쳤다는 표시)를 넣습니다.

**가. 손보기 전**

```bash
curl -s -D - -o /dev/null todo.localhost:8080/api/health | grep -i powered
```

**이렇게 나오면 성공**: `x-powered-by: Express`

**나. 파일 고치기** — `todo-api-route.yaml`을 아래처럼 고칩니다(규칙 하나로).

```bash
nano todo-api-route.yaml
```

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: todo-api
  namespace: todo
spec:
  parentRefs:
  - name: front
    namespace: gateway
  hostnames: ["todo.localhost"]
  rules:
  - matches:
    - path:
        type: PathPrefix
        value: /api
    filters:
    - type: RequestHeaderModifier
      requestHeaderModifier:
        set:
        - name: x-gateway
          value: front
    - type: ResponseHeaderModifier
      responseHeaderModifier:
        remove: ["x-powered-by"]
    backendRefs:
    - name: api-v2
      port: 3000
```

| 부분 | 뜻 |
|---|---|
| `backendRefs:`에 `api-v2` 하나 | /api는 모두 v2로(카나리 끝) |
| `filters:` | 보내기 전·돌려주기 전에 요청·응답을 손봄 |
| `RequestHeaderModifier` `set` | 앱에 가는 요청에 `x-gateway: front`를 넣음. 손님이 같은 이름을 보내도 **덮어씀** |
| `ResponseHeaderModifier` `remove` | 손님에게 가는 응답에서 `x-powered-by`를 지움 |

```bash
kubectl apply -f todo-api-route.yaml
for i in $(seq 1 20); do curl -s todo.localhost:8080/api/health; echo; done | sort | uniq -c
curl -s -D - -o /dev/null todo.localhost:8080/api/health | grep -ci powered
curl -s todo.localhost:8080/api/me; echo
curl -s -H "x-gateway: hacker" todo.localhost:8080/api/me; echo
```

**이렇게 나오면 성공**: 20번 모두 v2, `x-powered-by` 줄 0개, 앱이 받은 `gateway`가 `front` — 손님이 `hacker`를 보내도 `front`

```
     20 {"ok":true,"version":2}
0
{"version":2,"gateway":"front","client":null,"user":null,"apiKey":null}
{"version":2,"gateway":"front","client":null,"user":null,"apiKey":null}
```

<details><summary><b>이렇게 나오면?</b> — 자주 나는 오류와 해결 (눌러서 펼치기)</summary>

| 화면 | 원인 | 해결 |
|---|---|---|
| `"gateway":null` | `filters`가 규칙 밖(칸), 또는 apply 직후 | `cat todo-api-route.yaml`, 5초 뒤 다시 |
| `"gateway":"hacker, front"` | `set` 대신 `add`를 씀 | `set`으로 고쳐 apply |
| `x-powered-by` 줄이 1 | `remove` 값 오타 | `["x-powered-by"]` |

</details>

## 6단계. API 변환 — /v1·/v2를 /api로 바꿔 보내기

손님에게는 API 주소를 **버전과 함께** `/v1/…`·`/v2/…`로 내놓기로 했다고 합시다. 앱 안의 주소는 `/api/…` 하나뿐입니다. 앱을 고치지 않고 **입구에서 주소를 바꿔** v1·v2에 보냅니다.

**가. 바꾸기 전**

```bash
curl -s -o /dev/null -w "%{http_code}\n" todo.localhost:8080/v1/health
curl -s -D - -o /dev/null todo.localhost:8080/v1/health | grep -i decorator
```

**이렇게 나오면 성공**: `404`, 그리고 `web.todo…` — `/v1`로 시작하는 규칙이 없어 실습 1의 `todo`(나머지 전부 → web)가 받았고, web(nginx)에는 그런 주소가 없습니다

```
404
x-envoy-decorator-operation: web.todo.svc.cluster.local:80/*
```

**나. 규칙 둘 더하기** — `todo-api-route.yaml`의 `rules:` 맨 아래(5단계 규칙의 `backendRefs` 다음)에 이어 붙입니다. 들여쓰기는 5단계 규칙의 `- matches:`와 같은 칸입니다.

```bash
nano todo-api-route.yaml
```

```yaml
  - matches:
    - path:
        type: PathPrefix
        value: /v1
    filters:
    - type: URLRewrite
      urlRewrite:
        path:
          type: ReplacePrefixMatch
          replacePrefixMatch: /api
    backendRefs:
    - name: api
      port: 3000
  - matches:
    - path:
        type: PathPrefix
        value: /v2
    filters:
    - type: URLRewrite
      urlRewrite:
        path:
          type: ReplacePrefixMatch
          replacePrefixMatch: /api
    backendRefs:
    - name: api-v2
      port: 3000
```

| 부분 | 뜻 |
|---|---|
| `value: /v1` · `/v2` | 바깥 주소가 `/v1`·`/v2`로 시작하면 |
| `type: URLRewrite` | 보내기 전에 **주소를 바꿈** |
| `ReplacePrefixMatch` · `replacePrefixMatch: /api` | 맞은 앞부분(`/v1`)만 `/api`로. 뒤(`/todos`)는 그대로 → `/api/todos` |
| `backendRefs` `api` / `api-v2` | `/v1`은 v1로, `/v2`는 v2로 |

```bash
kubectl apply -f todo-api-route.yaml
sleep 3
curl -s todo.localhost:8080/v1/health; echo
curl -s todo.localhost:8080/v2/health; echo
curl -s todo.localhost:8080/v1/todos; echo
curl -s todo.localhost:8080/v2/me; echo
curl -s -o /dev/null -w "%{http_code}\n" todo.localhost:8080/v1/me
```

**이렇게 나오면 성공**: `/v1`은 v1, `/v2`는 v2가 답함. 앱에 없는 주소 `/v2/me`도 v2의 `/api/me`로 바뀌어 답함. v1에는 `/api/me`가 없어 `/v1/me`는 `404`

```
httproute.gateway.networking.k8s.io/todo-api configured
{"ok":true}
{"ok":true,"version":2}
[{"id":1,"title":"모니터링 공부"}]
{"version":2,"gateway":null,"client":null,"user":null,"apiKey":null}
404
```

- `/v2/me`의 `"gateway":null` — 5단계의 헤더 손보기(`filters`)는 `/api` 규칙에만 있습니다. **필터는 규칙마다 따로** 붙습니다(확인 문제 3)
- `/api/…`는 그대로 5단계처럼 동작합니다. 바깥 주소가 셋(`/api`·`/v1`·`/v2`)이 됐지만 앱 코드는 그대로입니다

## 끝났는지 확인
- ☐ 2단계 뒤 `/api/todos`는 `api.todo…`, `/`는 `web.todo…`
- ☐ 4단계 헤더 없이 100번 중 v2가 20번 안팎, `x-version: v2`면 모두 v2
- ☐ 5단계 뒤 20번 모두 v2, `x-powered-by` 없음, `/api/me`의 `gateway`가 `front`
- ☐ 6단계 뒤 `/v1/health`는 `{"ok":true}`, `/v2/health`는 `version: 2`, `/v2/me`도 답함

## 정리
- 모두 둡니다. 실습 3~5가 HTTPRoute `todo-api`(6단계까지 고친 것)와 v2의 `/api/me`를 씁니다
- v1(`api`)도 지우지 않습니다. 클러스터 안 `load` → web → api 길과 모니터링 과목의 지표 수집이 v1을 씁니다
