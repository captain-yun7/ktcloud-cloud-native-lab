# 시작하기 전에

실습 1을 시작하기 전에 한 번 읽어 주세요. 접속·붙여넣기·YAML 쓰기·PORTS 탭은 앞 과목과 같습니다. 자세한 설명은 [Kubernetes 실습 문서의 시작하기 전에](../../02-kubernetes/실습/00-시작하기-전에.md)에 있습니다.

## 1. 명령은 어디에 치나요

**이 문서의 명령은 전부 서버 VM의 터미널에 칩니다.** VS Code 왼쪽 아래에 `SSH: ktc-sNN`이 보이고, 터미널 맨 앞이 `lab@sNN:~$`이면 서버 VM입니다.

- 회색 코드 블록 오른쪽 위의 **복사 버튼** → 서버 터미널에 붙여 넣기. `#` 뒤는 설명(주석)이라 같이 붙여 넣어도 실행되지 않습니다
- `<포트>`처럼 꺾쇠로 감싼 부분은 본인 값으로 바꾸고 꺾쇠도 지웁니다
- 이 과목에서 직접 쓰는 YAML은 `~/apigw` 폴더에 둡니다(실습 1에서 만듦). `nano 파일`로 열어 붙여 넣습니다(저장 Ctrl+O → Enter, 나가기 Ctrl+X). 들여쓰기는 스페이스 2칸, 탭 금지

## 2. 클러스터가 떠 있는지 확인

모니터링 과목이 끝난 클러스터를 그대로 씁니다. 아래 네 줄로 확인합니다.

kubectl -n todo get pods
kubectl -n shop get pods | head -3

## 3. 브라우저로 보기 — PORTS 탭과 주소

이 과목의 입구는 VM의 **8080번**입니다(앞 과목의 Traefik 입구 80번은 그대로 둡니다). VS Code 아래 **PORTS** 탭에서 VM의 `8080`을 전달(Forward)하면 내 PC 쪽 포트 번호가 하나 생깁니다. 그 번호를 `<포트>`에 넣습니다.

| 화면 | 주소 | 언제 |
|---|---|---|
| todo (게이트웨이 입구) | `http://todo.localhost:<8080을 전달한 포트>` | 실습 1부터 |
| Prometheus | `http://prometheus.localhost:<80을 전달한 포트>` | 실습 5 (모니터링 과목과 같음) |
| 쇼핑몰 (게이트웨이 입구) | `http://shop.localhost:<8080을 전달한 포트>` | 미션 |
| todo (HTTPS) | `https://todo.localhost:8443` — VM 안에서 curl로 | 실습 8 |

- 대부분은 VM 안에서 `curl`로 확인합니다. `*.localhost`는 curl이 자기 자신(127.0.0.1)으로 보냅니다
- 실습 8의 HTTPS(8443)는 수업용 인증서라 브라우저가 "안전하지 않음" 경고를 띄웁니다. 확인은 curl(`--cacert`)로 합니다

## 4. 막히면 — 질문하는 법

1. 에러의 **첫 줄**부터 읽고, 그 단계의 **이렇게 나오면?** 표와 [자주 만나는 오류 한눈에](./99-자주-쓴-명령과-오류.md#자주-만나는-오류-한눈에)에서 같은 문구를 찾아봅니다
2. curl이 숫자(401, 404, 429, 503 …)만 돌려줬다면 그 숫자가 곧 단서입니다. 아래 상태 코드 표를 봅니다
3. 그래도 모르겠으면 Discord에 질문합니다. 에러는 **사진이 아니라 글자로** 붙이고, 아래 네 가지를 같이 적습니다

```
[실습 3 - 3단계] (몇 번 실습, 몇 단계)
한 일: curl -s -H "x-api-key: key-aaa" todo.localhost:8080/api/me
기대: "client":"team-a"
실제: Client authentication failed.
해 본 것: kubectl -n todo get securitypolicy apikey 결과 (그대로 붙여넣기)
```

## 이 문서에 나오는 말

| 말 | 쉬운 뜻 |
|---|---|
| API | 프로그램이 다른 프로그램을 부르는 주소와 약속. 여기서는 todo의 `/api/todos` |
| 게이트웨이 | 클러스터로 들어오는 요청이 처음 지나는 입구 프로그램 |
| Ingress | 쿠버네티스 과목에서 쓴 입구 규칙(이름·경로 → Service). 키 검사·횟수 제한 같은 일은 표준에 없음 |
| Gateway API | 쿠버네티스에서 입구를 적는 **새 표준 리소스** 묶음(GatewayClass · Gateway · HTTPRoute) |
| API Gateway | 입구에서 길 찾기 + 키 검사 · 횟수 제한 · 헤더 바꾸기까지 해 주는 것 |
| Envoy Gateway | Gateway API를 읽어 Envoy를 띄워 주는 프로그램. 이 과목에서 쓰는 API Gateway |
| Envoy | 실제로 요청을 받아 넘기는 프록시. Istio 사이드카(`istio-proxy`)와 같은 프로그램 |
| GatewayClass | "어떤 프로그램으로 입구를 만들지". 여기서는 `eg` |
| Gateway | 입구 하나(포트, 어느 네임스페이스의 경로를 받을지). 여기서는 `front` |
| HTTPRoute | 경로 규칙 하나(이 이름·경로로 오면 이 Service로) |
| 정책(Policy) | HTTPRoute에 **붙이는** 추가 규칙. `SecurityPolicy`(키·토큰 검사, CORS), `BackendTrafficPolicy`(횟수 제한, 재시도·서킷 브레이커). 같은 종류는 HTTPRoute 하나에 하나 |
| API 키 | 요청 헤더에 넣는 비밀 문자열. 누가 부르는지 구분 |
| JWT | 로그인 서버가 서명해 준 토큰. `헤더.내용.서명` 세 부분 |
| 속도 제한(rate limit) | 정해진 시간에 부를 수 있는 횟수를 넘으면 막음 |
| 카나리 | 새 버전을 일부 요청에만 먼저 보내 보는 것 |
| API 변환 | 바깥에 내놓은 주소(`/v1/…`)를 입구에서 앱이 아는 주소(`/api/…`)로 바꿔 넘기는 것(`URLRewrite`) |
| 타임아웃 | 요청 하나를 몇 초까지 기다릴지. 넘으면 입구가 끊고 504 |
| 재시도 | 뒤쪽이 실패하면 손님에게 알리기 전에 다시 보내 보기 |
| 서킷 브레이커 | 뒤쪽이 고장 나거나 넘칠 때 잠시 끊어 보호하기 — 고장 난 파드 빼기, 동시 요청 한도 |
| 출처(origin) | 주소의 앞부분 = `http`/`https` + 이름 + 포트. 하나라도 다르면 다른 출처 |
| CORS | 다른 출처의 화면이 API를 부를 때 브라우저가 서버의 허락 표시를 확인하는 규칙 |
| HTTPS · TLS | 내용을 암호화해 보내는 HTTP · 그 암호화 방식 |
| 인증서 · CA | "이 이름의 주인"이라는 증명서 · 그것에 서명하는 발급 기관 |
| 리스너 | 입구(Gateway)의 창구 하나 — 포트·프로토콜(HTTP/HTTPS)·이름 |

**HTTP 상태 코드** — curl `-w "%{http_code}"`가 보여 주는 숫자

| 코드 | 뜻 | 이 과목에서 보는 때 |
|---|---|---|
| 200 | 성공 | 정상 |
| 301 | 다른 주소로 가세요(`location`) | HTTP → HTTPS 넘겨 보내기 (실습 8) |
| 401 | 누구인지 확인 못 함 | 키·토큰이 없거나 틀림 (실습 3·4) |
| 404 | 맞는 경로가 없음 | 어느 HTTPRoute에도 안 맞음 (실습 1) |
| 500 | 입구 쪽 설정이 깨짐 | HTTPRoute가 보낼 Service를 못 찾음 (실습 1 7단계) |
| 429 | 너무 많이 부름 | 속도 제한에 걸림 (실습 5) |
| 503 | 뒤의 앱에 못 붙음 | 앱 파드가 없거나 연결이 끊김, 앱이 503을 줌, 동시 요청 한도를 넘음 (실습 6) |
| 504 | 기다리다 끊음 | 타임아웃을 넘음 (실습 6) |
